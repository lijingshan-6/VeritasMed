# v0.5 整段回答审计：本轮执行协议

2026-09-24。根据前两轮结果调整顺序：先做整段回答审计及真实记录面板，再决定专用核查模型的必要性。

## 本轮交付

- 输入为整段回答与提供的来源文本。每条判断绑定回答原文、来源原文及字符范围。
- 两种策略：直接审计整段回答；先提取连续原文中的陈述，再逐条核查。
- 不把生成的独立改写当作原 claim，保留未覆盖文本、无效引用、执行失败与未核查。
- 接入 RAGTruth 自然回答人工错误范围标注，用全部参考错误计算召回，漏提取仍算漏检。
- 最小面板提供回答/证据双向定位、原文上下文、真实保存记录重放、输入自有文本及 JSON 导出。

## 预先固定的评测口径

RAGTruth 固定提交 `c103204b9ce28d6bbad859304bf30de72b8ed8fe`；来源只使用 Summary 单文档任务。
本轮从官方 train、quality=good 中确定性抽取 24 个不同来源：12 份有标注错误、12 份无标注错误。
排除与官方 test 共享来源的候选，并核对所有训练候选的标注切片。
人工标注中的 `implicit_true` 仍作为“来源未支持”处理，单列数量；不把世界知识正确等同来源支持。
官方标注不重新改成医学三分类黄金标签，只比较“有无来源支持问题”及定位。

另登记 60 个官方 test 的 Summary 来源与响应 ID 作为预留样本，不在本轮调用，也不拿它调提示词。
这是按公开数据来源分组的预留，不能保证基础模型没有见过公开数据；尚不是已经完成的最终评估。

每份输入给两种策略相同的回答和全文来源。直接策略一次调用；拆分策略一次抽取后最多 24 次核查。
这不是等计算量比较：明确报告逻辑调用数、token 与时间。全局同时最多 3 个请求，无 Pro 回退。
先写入样本、代码哈希和提示词再调用，不依结果重新挑选或改标签。

### 指标

- 回答级：是否检出任意问题，precision/recall，干净回答误报。
- 原始错误范围：任意字符交集的检出率，以及至少覆盖一半错误字符的检出率。分母始终包含全部标注错误。
- 报错范围与人工错误范围的非空白字符 precision/recall/F1，防止整段标红轻易取得高召回。
- 抽取范围对全部错误的覆盖率，与后续核查检出率分开。字符重叠不是语义覆盖证明。
- 错误、无效引用、未核查、回答文本未覆盖范围，以及已报告用量。

三分类判断仅供观察，因 RAGTruth 原标注口径不同，不给它计算伪造的三分类准确率。
前两轮的已知 claim 核查、本轮整段回答审计分开报告，不能把它们当作模型提升曲线。

## 面板边界

面板只展示真实模型输出；保存记录明确显示重放，API 调用明确显示实时审计。
答案支持关系和原文位置联动。不显示“可信度 94%”，不将来源差异自动判为文献冲突。
词面覆盖不等于全部陈述完整覆盖；部分文本未审计时不能给整份回答一个绿色“全部可信”结论。
本轮提供独立审计入口，不自动改写答案，不接入补充搜索或医学证据分级。

后续按观察到的失败，选择改进抽取、引用绑定、语义核查或补充证据；完整工具调用对照另作实验。
