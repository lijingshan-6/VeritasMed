# 实验 A 设计（草案）：在公开题集上，这套系统比简单做法好在哪

状态：待确认，尚未下载数据或调用模型。

## 1. 要回答的问题

**同一个模型、同一批文献、同一套检索下，VeritasMed 的回答流水线是否比更简单的做法更少写出无依据的内容，同时答得一样准？代价是多少？**

附带回答两个产品问题：
- 「先概括再审计」与「关键事实逐字引用原文」相比，哪个更好？v0.9 刚改了这个默认做法，需要证据支撑。
- 审计能否发现回答中被植入的错误？误报率是多少？

## 2. 数据：PubMedQA

- **题目**：PQA-L 官方测试集（500 题，专家标注 yes / no / maybe），按固定种子分层抽取 **200 题**作为冻结测试集。开发集另取 **50 题**，来自 PQA-L 其余部分，用于调试提示和流程，不进入最终结果。
- **语料**：PQA-L 全部 1,000 篇摘要，再加 **10,000 篇 PQA-U 摘要作干扰**。只放 1,000 篇时，问题几乎就是论文标题，检索过于容易；加入干扰后检索才有难度，演示语料也随之扩到 1.1 万篇。
- **许可**：PubMedQA 为 MIT 许可，摘要来自 PubMed。
- **已知局限**：标准答案只有 yes/no/maybe，比较粗；模型可能在预训练中见过 PubMedQA。闭卷组（A0）专门用来度量后一个问题。

## 3. 对比组（同一个 Flash，同样的语料和检索）

| 组 | 做法 | 作用 |
|---|---|---|
| A0 闭卷 | 不检索，直接回答 | 下限，并估计数据污染 |
| A1 普通 RAG | 同样的混合检索加重排，取前 5 段，一次生成带引用的回答 | **主要基线**：最常见的简单做法 |
| A2 VeritasMed | 完整 Agent（v0.9 默认：概括回答，原句作为证据） | 被测系统 |
| A3 VeritasMed（逐字版） | 同上，但关键事实逐字引用原文（v0.8 做法） | 检验 v0.9 改动是否正确 |
| A4 金标准上下文 | 直接给出正确摘要，一次回答 | 上限：检索完美时能答多好 |

## 4. 指标

| 指标 | 怎么测 | 为什么可信 |
|---|---|---|
| **答案准确率**（yes/no/maybe，同时报 macro-F1） | 用同一个判定提示，把每组的回答映射成 yes/no/maybe，再与专家标签比对 | 外部专家标签；各组判定方式完全一致 |
| **无依据句子比例**（主指标） | 回答按句切分，每句与它引用的段落一起交给 **MiniCheck** 判断是否被支持 | MiniCheck 是独立的本地模型，与生成用的 Flash 不同源，避免"自己判自己" |
| 引用精确率 / 召回率 | 采用 ALCE 的定义 | 学界通用口径，可直接对照 |
| 检索命中率 | 正确摘要是否出现在最终使用的段落中 | 区分"没找到"与"找到了却答错" |
| 成本与延迟 | 每题 token 数、调用次数、耗时 | 回答"值不值" |
| **审计检出率 / 误报率** | 从 A2 选 100 个回答，每个各植入一处错误（数字、组别、否定、过度推断），连同原回答一起送 Direct 审计 | 错误由我们植入，标签是确定的 |

另用 Flash 做一次独立的引用判定，对 50 题的结果报告与 MiniCheck 的一致率，说明裁判本身的可靠程度。

**统计方法**：按题配对 bootstrap，给出 95% 置信区间；准确率差异用 McNemar 检验。所有指标定义和抽样种子在运行前冻结。开发集允许修改一次，测试集只跑一次，失败不重跑。

## 6. 预算估算

| 单元 | 每次 token（输入 / 输出） | 依据 |
|---|---|---|
| Direct 审计 | 1.2k / 6.9k | **实测**：run02 中 9 次调用的中位数 |

| 部分 | 总 token |
|---|---|
