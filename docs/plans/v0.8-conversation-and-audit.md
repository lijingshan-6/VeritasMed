# v0.8 详细计划：可持续的文献对话，逐轮可追溯的审计

制定：2026-09-27。起点：v0.7.1 产品修正与 v0.7.0 已发布研究。
状态：**2026-09-27 已完成版本收敛**。会话保存、答案版本、逐轮审计、显式上下文、
独立 atomic_v2 和三组真实医学回放已完成。R1 完成；R2 的 348 次预定审计全部保存，
R3 因新公开标签不足暂缓，Direct / Flash 保持默认。
[版本说明](../releases/v0.8.0.md) · [最终研究报告](../reports/verification-v0.8-report.md) · [实施记录](../archive/worklogs/development-v0.8-worklog.md)。

## 1. 本版要达到的效果

用户围绕一个医学文献问题连续提问，能够查看此前每轮回答，展开其中任意一轮的审计，
对照当时实际使用的原文；离开页面或刷新后还能恢复。审计指出具体证据关系和未解决项，
不把未检查显示成通过，不因核查器分歧自动抹掉原答案。

产品主线固定为：**Ask → 回答与来源 → 当前回答内 Audit → 追问 / 返回历史回答**。
Audit lab 和 Research 是辅助工作台。研究需要独立评测核查器，产品仍围绕对话组织。

v0.8 有两个必须同时推进的目标：

1. **产品完整性：**真正保存多轮问答、支持明确的上下文追问、每轮拥有自己的审计记录。
2. **审计可信性：**修正已有证据定位缺陷，测量限定语是否保留，解释并约束核查误拦。

本版不以“证明复杂 Agent 比强模型好”为完成条件。改进没有收益也须交付原始结果，
继续保留简单默认。版本完成与研究假设成立是两件事。

## 3. 交付边界

### 必须交付

- 一个以 Ask 为首页的连续问答工作区，真实历史记录、恢复与会话导出。
- 有明确边界的上下文追问，原问题、解析后的检索问题和使用的历史轮次均可查看。
- 每轮回答独立保存原文来源与审计；重新生成或重审追加版本，不覆盖旧记录。
- 父句范围内精确定位、限定语原文锚点及清楚区分的失败状态。
- 三组真实医学对话演示、无密钥的实际记录回放、完整启动说明。
- 定位修复、限定语保真和核查错误分析的研究记录；达不到默认升级条件就保持 Direct。

### 明确后移

- 审计结果自动改写最终答案，以及自动循环补检索到“通过”为止。
- 以研究设计判定因果效应、临床证据等级和跨文献冲突的最终裁决。
- 开放互联网研究任务上的 Agent 全面优越性声明。
- 自报可信度、模型多数票、未经适当评估的风险百分比。
- 医学模型微调、多模型扩军、云端账号同步、多人协作和企业审计平台。

不在 v0.8 同时重做所有 UI、接入多个供应商或重跑全部 v0.7 实验。

## 4. 产品设计与数据关系

### 4.1 对话与当前回答

中间区域按轮展示问题和回答；点击一轮即选中其来源、过程与 Audit。底部输入框保持固定。
回答工具栏提供 Audit、来源、复制/导出与重新生成；独立研究入口放在辅助导航。
运行状态用可读步骤展示，详细 trace 默认折叠。

追问产生新一轮，不覆盖上一答。重新生成同一问题产生新的 answer revision，保留上一次；
对应审计只属于其所核查的那个 revision。核查失败不隐藏回答，引用位置失败不等同于医学内容为假。
手工编辑审计输入后的运行标记为 edited experiment，不把结果回贴到未改动原答的审计状态。
只有回答与来源指纹一致的记录，才能作为该回答版本的审计展示。

### 4.2 最小数据模型

| 对象 | 必需字段与约束 |
|---|---|
| Conversation | id、标题、创建/更新时间、按序 turn IDs、schema version |
| Turn | id、conversation ID、原始问题、parent turn ID、selected context IDs、resolved query、状态 |
| AnswerRevision | id、turn ID、原回答、完整来源快照、引用映射、调用过程、模型元数据、完成/中止状态 |
| AuditRun | id、answer revision ID、策略/版本、输入指纹、原始输出、判断、位置、失败、费用与耗时 |
| SourceSnapshot | 内容指纹、原文字串、标题、文献 ID/URL、段落标识、取得方式；与回答一同固定 |

开始实现时增加 schema version，不以数组下标充当永久 ID。已有审计 JSON 保持可读；
旧 `vm_threads` 只能迁移为“无历史内容的旧会话标识”，不得生成不存在的消息。

### 4.3 本地保存与恢复

首版采用浏览器 IndexedDB 保存对话和来源快照，不增加账号或服务器数据库。保存失败明确提示，
仍允许导出当前记录；不默默清空老会话来腾空间。只保存任务数据，不保存 API 密钥。

必须实际演示：刷新恢复、切换会话、切换历史回答、审计重开、会话 JSON 导出/导入。
导入保留原版本与 provenance，数据不匹配时显示不可关联，不把近似来源套到旧审计上。
删除会话是显式用户操作；服务器 graph checkpoint 不冒充用户的持久聊天记录。

### 4.4 单次活动请求

继续沿用每个页面一个活动问答请求的简单规则。每次请求关联 conversation/turn/request ID；
取消、重试和迟到事件只影响对应轮次，不能写入用户后来选中的回答。
中止记录保存为 cancelled / incomplete，不作为完整答案参加审计。
这只处理真实产品中的串答问题，不建设分布式并发或任务调度平台。

## 5. 真正的上下文追问

### 5.1 显式上下文，继续隔离 graph 执行

扩展 Ask 请求以携带选中的历史轮次和当前问题。每次图执行仍独立初始化，不直接复用旧 checkpoint
中的 retrieved_chunks、repair_history 或 reducer 状态；这样保留已有请求隔离的正确性。

新增一个轻量的“理解追问”步骤，产生：

- 用户原始问题，原样保留。
- 用于检索的独立问题 `resolved_query`。
- 使用了哪些历史轮次、回指了哪些研究/人群/结局。
- `needs_clarification` 及具体缺失信息。

例如“那它的样本量呢？”只有在前文研究对象唯一时，才展开为指定研究的样本量查询。
前文有两项研究时请求澄清；不得静默任选一个。切换话题时不沿用旧研究、人群或结局限制。

第一版只取用户选择的上下文以及最近至多 6 个完整轮次，文本总量上限先定为 12,000 字符；
实际阈值在开发期冻结。只按完整轮次选择，提示未纳入的轮次，不能裁掉半个限定语再当完整历史。
更长会话先允许用户选择相关历史，不引入未经评估的自动摘要记忆。

### 5.2 历史回答不充当文献证据

旧回答可帮助理解指代和研究意图，但不能证明自己的说法。旧来源若复用，必须保留实际全文片段、
来源身份与指纹，并作为本轮输入来源显式列出；新检索来源也保存快照。
纯聊天文本与可引用的 source snapshot 使用不同字段，不混入同一证据列表。

不允许上下文解析修改用户的数值、否定或人群；解析不确定时保留判断或询问。
新增步骤的调用、耗时和 token 独立记录。旧单轮请求保持兼容。

### 5.3 对话功能验收场景

先写 12 段开发场景，每段 2–3 轮：4 段明确指代追问、4 段补充/修改研究条件、
4 段歧义/切换话题。给出预期研究对象、保留的限制和是否应澄清；它们是开发构造，
只验证对话契约，不能当临床或开放研究准确率。

至少覆盖：明确指代、多个研究的歧义、否定延续、时间/分母保留、换主题、继续旧轮次、
取消后重问、刷新后恢复、原回答与新版本的审计不串联。

## 6. 审计改进：先修可确定的问题

### 6.1 父句范围内精确定位（优先级最高）

以新策略版本实现，不覆盖 `atomic_v1` 或历史输出：

1. 在未改写的完整回答中精确定位 parent quote。
2. 父句唯一时，只在父句范围内查找每个 answer quote，再转换为全文 Unicode code-point 偏移。
3. 片段在父句内仍重复、父句不唯一或原文不存在时，继续保留 unresolved。
4. 来源引句同样只关联实际提供的 source ID/文字；不猜第一处、不模糊匹配、不重写原文凑匹配。
5. 每个位置保存所用范围、候选、状态与算法版本，允许回看为何恢复或拒绝绑定。

先对保存输出做纯离线重绑定，固定原始提取文本和模型判断。报告恢复了多少位置、仍有多少
歧义，以及新旧定位的逐项差异；这只能证明定位改进，不能作为语义判断变好的证据。

### 6.2 限定语保真与组别对应

新 `atomic_v2` 保存每项限定语的原文锚点，重点覆盖：人群、组别/比较对象、结局、数值/单位、
时间/分母、否定/归因。规范化 claim 仍标为模型解释，不能作为原文引句显示。

采用保守的提取方式：优先保留可独立阅读的原句/子句，必要时连接有出处的限定片段；
无法拆清时保留父级 compound / needs_review，不能为了原子化删除条件。
不根据来源的正确数字“修正”回答中的待审错误。相同事实的重复拆分只报告重复，不能充当更多独立支持。

可程序检查的项包括锚点是否存在、显式数字/单位是否遗漏、已声明组别与数值映射是否变化。
程序检查未报警不代表语义完全保真；代词展开、隐含条件和改写含义仍需独立诊断。
槽位齐全不是临床证据等级，也不是提取完整性的证明。

### 6.3 判断对象、引用错误和误拦分开

每个审计目标明确记录原回答事实、父句语境、提供的证据视图与引用单位。
统一句子/段落 ID 合同，避免把“整段输入的第 0 单元”误解释为模型可引用的第 1 句。
不自动修正模型返回的无效证据 ID 后宣称原运行通过。

分别呈现 model relation、引用可定位性、提取保真疑点及执行状态。引用格式失败不会被改成
contradicted；证据不足不会被显示成模型调用失败。核查器意见不自动决定原答案的显示与去留。

先诊断 v0.7 的 4 个保留项和 E2 的 3 个引用合同失败。它们已经曝光，只用于定位问题。
如果需要改核查提示，最多形成一个开发候选，与现行方法在同输入上比较；没有改善就不加入默认。

## 7. 有限、可解释的研究安排

### 7.1 先确定数据，再开始模型实验

P0 产出 exposure inventory：纳入旧开发/校准/最终来源、真实演示、构造变体、实际调用输入
和 v0.7 干扰论文。按文献关联连通组隔离，不能只排除 target ID 而复用看过的 distractor。
v0.6/v0.7 已曝光最终集只能作回归；60 个 RAGTruth 官方 test 来源仍保留。

新材料优先从已有公开数据中找未进入调用、回放或案例复核的来源。固定关系比较优先沿用
SciFact 公开标签；自然回答定位沿用 RAGTruth 的任务边界。P0 必须先报告合格来源数和类别，
本计划中的新样本数是目标，不是已经存在的独立黄金集。

没有足够未曝光的公开标签，就先完成定位/构造诊断和产品交付，明确“尚无新的语义泛化结论”；
不能用重新命名旧最终题、模型投票或 AI 自审补成新 gold。此时 Direct 不变，自动修复仍后移。

**2026-09-27 P0 结果：**排除关联来源及 v0.7 的全部干扰论文后，现有 SciFact 只剩 1 对
未曝光公开标签（insufficient），不足以开展下述 R3 新语义泛化比较，故暂不启动。
R2 还有 782 组机械筛选的医学数字候选和 701 个可选 RAGTruth train Summary 来源；
候选尚需按原文构造审阅，不能直接称为已标注题集。见[盘点与范围决定](../reports/verification-v0.8-exposure.md)。

### 7.2 实验矩阵

| 编号 | 对照与输入 | 主要回答什么 | 证据地位 |
|---|---|---|---|
| R1 定位 | 全部已保存 v0.6 Atomic 输出：原全局绑定 vs 父句范围绑定，模型输出固定 | 是否正确消除重复短片段导致的定位失败？ | 离线回归；不是语义提升 |
| R2 保真 | Direct、atomic_v1、atomic_v2；同回答、同来源 | 新拆分是否保留限定语、组别对应和待审错误，减少遗漏/重复？ | 来源明确的构造诊断 + 单列自然案例分析 |
| R3 核查 | 当前 Flash 核查合同 vs 一个明确的开发候选；同一固定目标和证据 | 能否减少误拦，且不增加错误放行？ | 有新公开标签才做冻结后比较；否则仅开发诊断 |

R1 先做。R2 只保留一个最终候选，不做提示词全排列。R3 只有发现可复现的具体问题才发新调用；
不为版本号再跑 MiniCheck 全套校准、三臂工作流或无改动的历史模型比较。

**R2 目标：**24 个来源组，12 开发 / 12 冻结检查；每组 4 个明确构造的回答，共 96 个。
形式覆盖原句、保真改写、跨片段/回指限定与重复短语；组别/数值对应和需保留的条件在调用前标定。
显式错误控制另标期望保留的错误内容，提取器不得提前修正。这些控制包含在上述 96 个回答内，
具体分配在清单中预先固定，不额外追加未声明样本。完整的字段、锚点、构造变换、原文出处和
疑点全部入库；有争议的构造在模型比较前修订或排除并留记录。
这是 AI/开发者构造的约束检查，不是独立医学专家语义 gold。

另从未用的 RAGTruth train 来源预选 12 个自然回答做 Direct / v1 / v2 开发对照，
按来源固定 6 个有标错与 6 个未标错。错误位置重叠、完成率、未标错警报分别报告；
未标错不代表完全正确，不能把警报直接叫假阳性。自然样本不与构造样本合并为准确率。

**R3 目标：**新公开标签至少 60 个 claim–document 配对、至少 40 个来源组；争取
supported / contradicted / insufficient 各 20 对。按来源分开发与冻结区，冻结区至少 30 组。
类别或数量达不到时在推理前调整规模、说明限制；不得观察最终输出后删难例或重新平衡。
只有真正改变核查合同才做两臂；不改变时交付失败分析，不重复收费测量同一个模型。

### 7.3 分母、重复与结论

- R1：可绑定率、错误跨父句绑定、保留歧义数；逐项位置可复查。
- R2：原文限定语锚点召回、显式组别/数值映射保持、重复/复合项、漏提取、未检查与完整回答数。
  自动可判定部分与 AI 语义开发复核分表，不把字符覆盖称语义保真。
- R3：三分类、supported vs non-supported、错误放行、正确支持召回、弃权及引用失败；全量分母保留。
- 记录调用、token 与实际耗时。Atomic 最多 3 次调用、48 事实；Direct 保持其原本的一次调用。
  不把不同调用量的差异全部归因于结构；必要的预算对照优先复用预定重复。
- R2 开发区提前选 6 个来源/回答，Direct 与最终候选各总计 3 次；不得按第一次好坏选择复测题。
  该重复衡量稳定性，不以多数票生成正确标签。
- 最多两轮开发修订；最终候选冻结代码、提示、清单及标签后再运行保留区一次。
  最终失败不择优重试；基础设施重试另留运行身份。
- 使用来源组配对差值和区间，解释小样本限制。来源相同的四个变体不能当四个独立研究。

默认升级仍沿用 v0.6 的原则：候选减基线的错误放行率差，其配对 95% 区间上界低于 0；
正确支持召回率差的区间下界不低于 -3 个百分点，且无已知系统性限定语丢失。
3 个百分点是项目研究决策标准，不是临床安全线。
定位算法可按机械正确性改进，语义策略不能因此一并升级；小样本证据不足就保持 Direct。

## 8. 实施顺序与每阶段交付

| 阶段 | 工作 | 可查看的结果 | 进入下一步的条件 |
|---|---|---|---|
| P0 约定 | 确定会话 schema、上下文合同、数据曝光清单与实际实验规模 | 产品示例流程、接口草案、数据清单 | 不把旧历史当新数据，不混淆会话语境与来源证据 |
| P1 连续会话 | 多轮消息、选中回答、IndexedDB、审计关联、恢复/导出 | 可刷新恢复的一段对话，每轮来源和审计独立 | 旧记录不串入新答案；错误/中止可见 |
| P2 上下文 | 追问解析、显式历史选择、歧义澄清、独立 graph state | 12 段场景及实际解析问题；原问题不变 | 问题对象、否定与范围不被静默改写 |
| P3 定位与保真 | 先 R1；再 atomic_v2 和原文限定语 | 新旧定位对照、父句/限定语联动、逐项失败 | 机械定位可复查，困难事实不会被丢掉换高完成率 |
| P4 有限研究 | R2 开发/重复；必要时 R3；冻结候选与保留区评估 | 原始输出、分开计分的报告、默认决定 | 结论与数据证据等级一致；无提升也如实收敛 |
| P5 演示发布 | 三组真实医学对话、无密钥回放、README 与版本说明 | 别人下载后能完整演示对话与逐轮审计 | 主入口清楚、原文可追溯、历史研究不被覆盖 |

按集中开发估计约 8–12 个工作日：P0 半天，P1 2–3 天，P2 1–2 天，P3 1–2 天，
P4 2–3 天，P5 约一天。只是工作量估计；数据不足或接口阻断时如实缩小结论，不降低数据质量。
先交付可用的会话框架，再分阶段合入审计改进，避免等全部实验完成用户才能看到产品变化。

## 10. 演示与文档

至少选择 3 篇有明确再分发条件的原始医学文献，组成三段各 3 轮的真实对话：

1. 同一研究的结果 → 人群/时间 → 指定结局的原文依据。
2. 多对象比较 → 明确指代追问 → 对象歧义时澄清。
3. 给定证据不足 → 保留判断 → 查看已有来源和未检查项。

选择与脚本在推理前固定，不挑最漂亮的输出；未完成和审计分歧同样回放。演示只证明所展示
的流程与具体输出，不计入独立最终评测。不能把系统生成的对话当人工专家答案。

默认文档先讲完整 Ask；另提供无密钥的真实对话回放。回放要明确 SAVED INFERENCE，
只有固定记录可选择，不能把预录答案套给任意问题或冒充当前模型正在生成。
原始医学出处、来源范围、每轮记录及全部审计可导出。

计划交付文档：`docs/conversation-guide.md`、`docs/reports/verification-v0.8-report.md`、
`docs/releases/v0.8.0.md`，同步 README、文档索引、研究复现与路线。报告实现后再写，
现在不创建带成功结论的占位报告。

## 12. 持续决定

Flash 为研究基线，最多 3 个 API 请求同时进行；没有例行 Pro 回退或 Pro 裁判。
