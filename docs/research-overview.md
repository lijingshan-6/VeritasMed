# 研究总览：目前能证明什么

截至 v0.8，VeritasMed 已有可运行的文献问答、逐条审计和可追溯实验记录。
**它尚未证明整段医学回答的审计足够可靠，也未证明规定的 Agent 工作流优于同模型自主调工具。**
这不是缺少一个漂亮的总体分数：现有实验回答的是不同问题，不能相加成“系统准确率”。

## 报告质量与现在的缺口

当前较扎实的是：给出来源/输入、固定合同、保留失败、比较简单对照，并对负结果明确作决定。
v0.6 固定目标有外部标签；v0.7 用相同候选与工具约束比较；v0.8 则明确只测机械指标。
研究记录足以解释为什么继续使用 Direct / Flash，而非用更复杂的结构替换默认。

最明显的限制仍是 **自然医学整段回答的语义参照不足**。来源定位、数值共现、模型一致、
public error span overlap 都不能补上这块。当前公开来源池也不足以开展原定 R3：
P0 时仅剩一对可用且未曝光的 SciFact 公开标签。该数量是调用前快照，不是持续更新的余额。

其次，完整 Ask 的检索/生成修复、独立 Audit、受限 Research 分别已有实验，尚无一套外部标签
贯通“原问 → 找文献 → 回答 → 审计 → 修复”的端到端研究。v0.4 分数不能沿用为 v0.8 多轮成绩，
12 条上下文开发合同的第二次 12/12 也不能掩盖真实演示的歧义失败。

标签同样可以有疑点。v0.6 Natsal-3 的来源视图问题有单独敏感性分析；v0.8 的若干 RAGTruth
样本有事后 AI 阅读分歧。原标签和主结果都保留，不能因为本系统不赞同就删除不利样本。

## 怎样继续研究才有价值

1. 把当前三类具体失败转为明确任务：该澄清时澄清、区分写作约束与证据缺口、回答每个子问题。
   这些是开发问题；来自现有演示的回归成功不能再称独立测试成绩。
2. 为整段审计寻找新、明确许可且能追溯标注过程的外部语义数据，预先固定所见文本视图。
   专家无法参与时如实保留限制，不用多个 AI 投票冒充独立人工标注。
3. 有合格外部参照后，才比较相同底模/来源条件下的 Direct、原生自主工具与特定 Agent 改动。
   每次回答一个问题，同时报告漏报、错误放行、正确支持召回、覆盖、失败、token 和延迟。
4. 审计能稳定识别目标错误之后，再研究它是否能指导补检索/修复；保留原答，外部标准评修复。
   校准和跨论文冲突裁决继续单列，不靠产品面板中一个绿色标识宣布完成。

下一步已具体化为 [v0.9 问题覆盖研究](plans/v0.9-question-coverage.md)：先判断外部论文问答
参照是否适用，再比较直接审阅、请求项结构与同调用次数对照。它补任务完整性的缺口，
不冒充新的医学语义 gold。当前只完成设计，没有启动付费调用或解锁保留集。
