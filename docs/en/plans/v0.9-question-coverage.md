# v0.9 research plan: answers need support and completeness

**English** | [简体中文](../../plans/v0.9-question-coverage.md)

Status: design settled on 2026-09-27; no new dataset downloads, final-partition access or model
comparisons have started. Flash / Direct stays default. This follows v0.8 without changing its
published tag or historical results.

## 1. Research question

**For the same question, answer and sources, can explicit user-request items detect more omitted
subquestions than a single direct model review, without unnecessary clarification or mistaking
writing constraints for literature gaps?**

Claim auditing primarily checks whether statements that were written have support. It cannot see
requirements never written, so every sentence may pass while the task remains incomplete.
v0.8 medical conversations retain three development counterexamples:

| Exposed failure | What the new check should recognize | Invalid shortcut |
|---|---|---|
| “It” after two papers: no clarification, durations given for both | Whether the reference is unique; ask which paper if not | Do not force the most recent paper as referent |
| “Do not compare efficacy” treated as an evidence gap | Separate expression constraints from evidence-bearing questions | Following a constraint is not missing evidence |
| Three-hour glucose answered, five-year mortality omitted | Each explicit subquestion needs an answer or a stated source-scoped gap | Passing claims do not mean the whole task is solved |

These are development regressions, not an independent final score. See
[research overview](../research-overview.md) and [v0.8 report](../reports/verification-v0.8-report.md).

## 2. Intended product

Ask stays the main entry; Audit stays within the current answer. Add “question completion” beside
“source support for statements”:

- List each explicit request, linking to the original question, corresponding answer text and existing sources.
- Distinguish answered, explicit insufficiency within supplied sources, omitted, clarification needed and check incomplete.
- List writing constraints separately, such as not comparing efficacy; do not treat them as clinical endpoints to retrieve.
- “Answered” describes coverage only; correctness/support still rely on that sentence's Direct audit.
- Preserve the original answer by default. Users can follow up on omissions; this version will not let the new checker rewrite automatically.

No overall confidence percentage, cross-paper conflict adjudication or clinical applicability grade.
Do not average the panels into one score. Bind all checks to the same answer version and input fingerprint.

## 3. Minimal technical route

Add an independent `question_coverage` module: first offline saved inputs, then UI integration.
Do not pile keyword patches into old `nodes` or alter frozen Direct / Atomic inference files.

```text
Original question + explicitly selected bounded history
  → request extraction (question anchors, referent, factual question / writing constraint)
  → preserve ambiguity / await clarification, or obtain explicit request items
Original answer + complete supplied sources + request items
  → locate response / explicit gap / omission / incomplete check for each item
Existing Direct audit
  → separate statement support; does not decide coverage
```

Proposed objects: `RequestItem(id, question_spans, kind, referent, status)` and
`CoverageItem(request_id, answer_spans, source_ids, disposition, reason)`.
Original question text stays unchanged. Generated items must anchor to it; unknown anchors cannot
be valid completed items. Missing outcomes are stated as “not established in the supplied text,”
never as absent from all medical knowledge.

Decomposition/referent recognition can fail: retain extractions, uncovered question fragments,
failures and raw replies. Mechanical anchors establish positions, not correct semantic extraction.

## 4. Data: external labels separate from constructed diagnostics

Without clinical experts, do not create “medical gold” through self-review or model votes.
First investigate **QASPER**: questions and answers from different NLP practitioners, with supporting
evidence, in paper Q&A rather than clinical medicine. Sources:
[original paper](https://aclanthology.org/2021.naacl-main.365/) and
[Ai2 dataset card](https://huggingface.co/datasets/allenai/qasper), labelled CC BY 4.0.
It is suitable for investigating source-scoped answerability; **it does not already label this project's omission-audit task**.

| Layer | Content and reference | Use and limits |
|---|---|---|
| A: original external task | Original QASPER question, full text, human answers/evidence and unanswerable labels | Answerability and official answer/evidence metrics; Answer F1 is not omission-checker accuracy |
| B: recorded construction diagnostics | Two explicit questions from one paper, original extractive references; paired complete/omitted answers | Known deletion and request coverage; synthetic labels, not natural-answer generalization |
| C: real medical application | Three exposed conversation failures plus new traceable demonstrations | Product transfer/failure types; AI reading is diagnostic, not external accuracy |

P0 reads at most 10 official train papers and records every ID as exposed. Inspect raw fields,
licenses, paragraph location, annotation disagreement, table dependencies and contradictions such
as unanswerable items with answers. An upstream [label-field discussion](https://github.com/allenai/qasper-led-baseline/issues/17)
means public human labels cannot be assumed infallible. Retain all annotations; decide primary
eligibility before seeing model outputs.

During design, the official page preview exposed parts of ten train papers:
`1909.00694`, `2003.07723`, `1705.09665`, `1908.06606`, `1811.00942`, `1805.02400`,
`1907.05664`, `1910.14497`, `1912.02481`, `1810.04528`. The issue also displayed three dev question IDs:
`a5e49cdb91d9fd0ca625cc1ede236d3d4672403c`, `6a633811019e9323dc8549ad540550d27aa6d972`,
`a8c862d8c5da3f060eedf3395a3d0a97fd8a12d8`. P0 must exclude their entire papers from the final partition.
No data downloads, test reading or model calls have occurred; page previews are not wholly unseen.

Target size: **30 development papers, 60 frozen evaluation papers**, from official train / validation.
Deduplicate project data by paper ID, title and body hash; leave official test untouched. Previously
read train examples are development only. All questions/variants from one paper belong to one
partition. Select final data with a fixed seed/predefined strata, never model performance. Call
this “project-frozen evaluation,” not proof that public data were absent from provider pretraining.

Diagnostics target two clear, distinct questions per paper and four versions: complete, first item
omitted, second item omitted, complete plus a writing constraint. Remaining text must not incidentally
answer the deleted question. Ambiguous cases are ineligible with reasons recorded; AI agreement
cannot replace this check. Paraphrases/referent ambiguity are separate development stress cases,
outside mechanical primary tables. Original references are not new answers generated by this system;
new combinations cannot be passed off as original-author annotations.

**Feasibility gate:** before any comparison calls, freeze dataset revision, selection code, text
view, inclusion/exclusion records and actual denominators. If too few qualify, shrink explicitly to
a pilot rather than padding with old final questions. Without directly inspectable deletion
references, deliver only development diagnostics/UI, not a new reliability-improvement claim.
Keep the 60 RAGTruth official test sources reserved. Exposed SciFact final items are regression only.

## 5. Comparisons: do not mistake complexity for efficacy

Same Flash, source texts, input limits and settings. Fixed-input auditing comes first, avoiding
retrieval quality as a confound.

| Arm | Implementation | Question |
|---|---|---|
| A Direct coverage | One call directly checks omissions, constraints and ambiguity; minimal comparable states | What can a strong model's direct review do? This is a new coverage baseline, not old Direct claim audit |
| B Structured coverage | Extract question-anchored requests, then check each; at most two calls | Does explicit decomposition add value? |
| C Two-pass direct | Two calls; directly review the first omission judgment without a structured request list | Is any gain simply another model call? |
| D Oracle requests (diagnostic only) | Give B the known construction requests, then check the same answer | Is failure extraction or matching? Privileged references prevent deployable-winner claims |

Deployable arms receive identical raw inputs. Each arm's total output ceiling is 16,384 tokens per
input: A may use it once; B/C permit 8,192 per call. Save actual input/output/reasoning usage,
calls and latency separately. Equal ceilings do not imply equal compute. If an endpoint cannot
honor this, revise the protocol in P0 before development comparisons, never relax it for one arm.
Concurrency at most three is a run setting, not new service architecture. Malformed outputs/timeouts
remain failures, with no best-of retries.

Development permits one candidate revision, retaining all before/after runs. Final frozen A/B/C
run each item once. Preselect six development inputs for three repeats per arm; report inconsistency,
not the best response. D is outside final winner comparison. Once final tables are opened, do not
modify a candidate from their results and rerun them as new performance.

## 6. Primary metric and upgrade criteria

**Primary: erroneous “fully answered” acceptance rate** among known-omission versions. Also report
omission recall, correct acceptance of complete references, writing-constraint false alarms, valid
execution and every raw count. Failures are separate and included in scheduled denominators;
also report completion-conditional metrics to avoid appearing safe by abstaining often.
Request extraction precision/recall applies only to construction-known requests; character
coverage cannot substitute for semantic completeness.

Layer A separately reports original answerability confusion and Answer / Evidence F1 under official
multiple-reference rules. Layer B omission diagnostics and Layer C medical observations stay
separate, never one “system accuracy.” Paired paper-group resampling gives descriptive 95% intervals:
all variants sampled together, fixed seed and 10,000 repeats.

Necessary conditions to make B default: against both A and C, the frozen diagnostic false-acceptance
difference interval must have its upper bound below zero; the lower bound of complete-reference
correct-acceptance difference must be at least −5 percentage points; valid execution must be ≥95%.
These are engineering tradeoffs, not clinical safety standards. Failure/wide intervals keep A or
an experimental switch, with negative findings published. Even success supports only improvement
on these recorded constructions, not reliable natural medical auditing.

No general clarification accuracy yet: fix exposed failures, retain ambiguous/unambiguous development
controls and additional-question burden. Without independent conversation labels, perfect handwritten
context examples cannot establish multi-turn generalization.

## 8. Why Agent research remains necessary

This version tests one structural idea—request items—not the whole Agent. If useful, a later version
compares one targeted completion after checking with strong-model direct re-answering. Preserve
originals; external references evaluate repair gains/new errors. Only then expand to open retrieval
and native autonomous tools with equal tool access, information permissions and budgets. Report
provider-native tool limitations explicitly.

Clinical applicability, causal-design grades, cross-paper comparability and conflict adjudication
remain independent projects. New external semantic verification data are still needed; QASPER
provides question/evidence references, not a solution to the medical gap. Conclusions must permit
“the simple model suffices” or “structure adds false alarms,” rather than presupposing Agent superiority.
