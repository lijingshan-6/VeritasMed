# v0.8.0 — Conversations with an audit for each answer

Ask now keeps a conversation rather than replacing the last answer. Each question has
its own answer versions, sources, trace and audit history. You can ask a follow-up,
return to an earlier answer, reload the page, or export the complete conversation.

Source milestone: `v0.8.0`, with the same implementation and records on `main`.
This is a source/tag release; a separate GitHub Release page is not part of the milestone.

## Product

- **Persistent conversations:** browser IndexedDB, selected-turn recovery, answer versions,
  per-answer audit records, export/import and visible interrupted or failed requests.
- **Explicit follow-up context:** up to six whole prior turns and 12,000 Unicode characters.
  The original question remains unchanged; resolved references are shown separately.
  Each answer retrieves evidence anew. Prior answers never become source evidence.
- **Audit within Ask:** inspect Direct or experimental Atomic v2 results on the selected
  answer, navigate exact source passages, and return to the conversation. New audit runs
  append records rather than replacing the previous result.
- **Qualifier inspection:** Atomic v2 locates an exact parent passage, answer fragments and
  qualifier quotations. Missing, ambiguous, compound and uncertain items remain visible.
  Original model relations are distinct from whether a check completed.
- **Three actual medical conversations:** nine recorded Ask answers and twelve saved audits,
  using fifteen original abstract sections from three attributed papers. The questions
  were fixed before inference; refusals and incomplete answers are kept unchanged.

## Run the showcase

The [README](../../README.md) provides the complete installation recipe. With the light
requirements installed, run:

```sh
python scripts/run_showcase.py
```

Open **http://127.0.0.1:5173/** and choose a **SAVED INFERENCE** conversation. Replay needs
no model key, GPU, vector database or corpus download. Select a question, open **Audit**,
switch **Saved runs**, inspect original passages and export the conversation.
Replay makes no model calls and does not accept new questions.

For new questions, install the full retrieval dependencies, configure Flash, stop the
replay service and run:

```sh
python scripts/run_demo.py --conversations
```

This indexes only the three demo papers; it is not an unrestricted medical evidence base.
The older one-paper `--medical` profile and the standalone audit/research workspace on
5174 remain available. Ask at 5173 is the main product.

## Research and the default decision

**Direct / Flash remains the default.** There is no Pro fallback, automatic candidate
promotion, calibrated confidence percentage or automatic adjudication of literature conflicts.

R1 replays 167 earlier Atomic audits without model calls. Parent-scoped matching recovers
82 fact locations, increasing bound facts from 1,097 to 1,179 of 1,203, with no regressions
and 24 unresolved facts. This changes locations, not the original semantic judgments.

R2 compares Direct, Atomic v1 and Atomic v2 on source-separated constructed diagnostics,
with natural-answer development cases and predetermined repeat runs. Its exact-phrase
coverage, qualifier co-presence and numeric retention measures are **not clinical accuracy**.
All **348 scheduled audits** are preserved: 144 constructed development, 36 natural development,
24 additional repeats and 144 post-freeze final audits. They contain 577 model calls and
4,529,930 provider-reported tokens. No candidate revision or selected final retry was used.

| Final method | Complete audits | Targets with all anchors in one claim | Number + target conditions retained |
|---|---|---|---|
| Direct | 47/48 | 91/104 | 83/96 |
| Atomic v1 | 26/48 | 81/104 | 71/96 |
| Atomic v2 | 26/48 | 101/104 | 93/96 |

V2 retains more targeted conditions in this construction, with more review-needed items.
Its source-group intervals for co-presence and numeric retention include zero; these metrics
also cannot establish semantic improvement. Completion criteria differ between methods.
The separate natural development sample completes 12/12 for Direct and 3/12 for v2, with
the same 8/12 annotated error spans overlapped by warnings. All original labels and disagreements
remain, including three additional AI observations about ambiguous public-label/source interpretations.
Full tables, intervals, repeats and outputs are in the [v0.8 report](../verification-v0.8-report.md).

R3 is deferred: the source-exposure inventory leaves only one fresh public SciFact label,
which cannot support a new three-class semantic generalization comparison. AI-generated
cases and AI review are not substituted for independent gold labels.

## Functional validation

The lightweight setup was installed in a clean Python environment and opened in the browser:
all three conversations, source context, saved Direct/v2 runs, qualifier navigation, reload
recovery and export/import into a separate browser session worked. Screenshots show those
actual records. The full three-paper Ask service was then restored for new questions.
Both launchers now wait for their local API before starting the frontend.

271 Python tests, 7 frontend tests, the production frontend build and historical report
reproduction checks passed. These checks concern software behavior, not clinical accuracy.

## Known limits, visible in the release

- In the two-study demo, the resolver answers both study durations instead of clarifying
  the ambiguous singular reference. It also treats “do not rank their effectiveness” as
  an evidence question, producing an unnecessary partial-coverage label.
- The last exercise follow-up quotes the glucose-duration sentence but omits an explicit
  answer to the five-year mortality clause. The answer remains marked partial. A completed
  quotation audit does not prove the entire question was answered.
- Atomic v2 can retain more original conditions while returning more review-needed items.
  Literal-number rules can flag reasonable splitting; absent flags do not establish completeness.
- History is browser-local and currently assumes editing in one tab. Export valuable records;
  clearing site data removes local history. No cross-device account sync is provided.
- Only abstracts are indexed in the medical demo. Research labels, constructed controls,
  recorded demonstrations and historical evaluations retain their separate evidence roles.
