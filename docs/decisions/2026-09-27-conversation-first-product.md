# 产品方向：对话为主，审计属于回答

日期：2026-09-27。来源：用户指出 v0.7 演示只剩 Audit / Research，与原定产品不符。

## 问题与原因

为了独立测量核查器并降低演示依赖，增加了 `run_audit_demo.py` 与 5174 轻量服务。
原 Ask/Explore 没被删除，仍在完整应用 5173；但轻量入口隐藏了它们，README 与默认展示也
转向审计实验。Ask 的 Audit 又跳转到独立页面，使技术模块的隔离变成了产品流程的割裂。
研究拆分有必要，这种产品入口安排需要纠正。

## 确定的产品关系

1. Ask 是主入口：提问、查看回答及来源、审阅回答、继续提问。
2. Audit 是当前回答的审阅模式，保留原问题、答案、完整来源与输入框；不自动改写答案。
3. Audit lab 保留独立输入和保存实验回放，Research 保留方法比较。二者都是辅助工作台。
4. 核查器独立接口与研究评测继续存在，不要求用户为了审阅一个回答切换到另一个产品。
5. 可信度、文献冲突、自动修复仍以实际能力和独立评估为前提；产品整合不改变既有研究结论。

## 本次纠正

- Ask 的 Audit 按钮在当前页面内展开现有审计组件，不修改原回答或来源。
- 明确点击 Run audit 才推理；Back to answer 关闭视图，重开保留当前审计。
- 底部提问输入保持可用，新问题清除上一回答的审计上下文。
- 轻量页面补回 Ask 链接与运行范围说明，README 首先说明完整产品入口。
- 独立 Audit lab 使用应用内导航，避免整页刷新导致当前 Ask 回答丢失。

完整会话历史持久化、切换不同历史回答的独立审计记录，仍须另做产品设计。
本次不把现有 thread ID 或“最近会话”菜单描述成已经具备完整聊天记录恢复能力。
v0.7.0 原始标签和研究工件保持不变，以上作为 v0.7.1 界面修正交付。
后续实现范围见 [v0.8 详细计划](../plans/v0.8-conversation-and-audit.md)。
