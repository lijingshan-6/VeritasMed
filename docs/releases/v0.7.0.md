# v0.7.0 — Audits measured, workflows compared

**2026-09-27 — source milestone `v0.7.0`.**

This milestone brings together the v0.6 audit-reliability work and the bounded v0.7 workflow
comparison. There is no separate v0.6.0 release. The full medical Ask graph and all historical
results remain available.

## Product changes

- An experimental atomic audit retains parent sentences, original answer fragments,
  normalized model interpretations and explicit qualification slots. Ambiguous locations,
  compound/uncertain parses and unchecked facts stay visible.
- Separate Flash and optional MiniCheck outputs can be inspected without voting them into
  a confidence percentage. Numeric rules are advisory and retain unresolved contexts.
- Three GRADE inputs distinguish an unchanged real Agent answer, deliberately swapped arm
  values and deliberately removed result evidence. Saved records require no API key or GPU.
- `/research` replays three shared-tool workflows, their original answers, evidence and full
  call traces. The public reference is withheld during inference; the displayed final table
  uses a separate source partition. Answer transfer to Audit makes no automatic model call.
- The same lightweight launcher serves both pages. MiniCheck and the full retrieval stack
  remain optional, separate installations.

## Research and interpretation

The fixed-claim evaluation is complete: 339 pairs across 247 connected source groups from
SciFact's public dev set. Flash and MiniCheck completed every pair. Binary correctness was
291/339 versus 279/339, non-support accepted was 6/201 versus 14/201, and supported recall
was 96/138 versus 92/138. MiniCheck's false-acceptance rate minus Flash's was +3.98 percentage
points (paired source-group 95% interval +0.49 to +8.11). Its faster local scoring did not
justify replacing Flash. Binary scores merge contradicted and insufficient; Flash's full
three-class label agreement was 269/339.

The independent threshold-selection partition found no eligible MiniCheck acceptance policy.
The frozen score mapping slightly lowered final Brier score, from 0.1395 to 0.1306, but this
does not establish a usable threshold or clinical probability. No final-set threshold tuning
or per-claim confidence percentage is published.

On 36 natural development answers, Direct / Split / Atomic completed every extracted check
on 34/36, 35/36 and 11/36 answers. Atomic's explicit structure also exposes ambiguous fragments,
uncertain decompositions and qualifier loss. On 12 repeated sources, alarm presence changed
on 2/12 for Direct and 4/12 for Atomic. **Direct remains the default; Atomic and MiniCheck are
research options.** Error-span overlap and model agreement do not establish semantic accuracy.

The medical transfer study completed all 96 scheduled records (32 answers × three methods),
including partial audits. These remain construction diagnostics, separately reported from
public-label fixed claims and natural answers.

On 40 frozen final named-paper queries, direct reading and autonomous tools each completed
40/40 and made 35/40 correct accepted binary decisions. The structured workflow completed
36/40 with 31/40 correct accepted decisions; its unfiltered draft score was 35/40. All three
accepted non-support in 2/19 cases. The check held three correctly supported drafts and one
contradicted/insufficient disagreement that was correct only under the binary score. It did
not reduce false acceptance. Reported tokens were lower for the structured workflow, but
latency was higher and support recall lower. This study does not justify upgrading the default.

The study separates public-label fixed claims, developer/AI medical constructions and natural
answer localization. The source-view issue in medical-15 is recorded as a label qualification;
frozen labels and primary outputs remain intact, with a separate post-hoc sensitivity view.
Neither AI review nor repeated model agreement is independent expert gold.

The workflow task asks whether a named paper supports a claim among eight fixed candidate
abstracts. Direct reading uses one model call; autonomous and structured tools have the same
six-model-call/eight-tool-call limits, with verification charged to that model budget. The
autonomous arm uses a validated application-level JSON action protocol.

Its first development round exposed conflicting finish instructions and mixed JSON/DSML
replies. All 60 records are retained. Before any final inference, the action contract was
clarified and a second complete development round recorded format normalization: discarded
trailing tool text is never executed or used as evidence. The final comparison uses this
revised, frozen protocol; the broken first adapter is not evidence against autonomous models.

This comparison does not establish superiority of the historical full Ask graph, open medical
research, clinical evidence grading or cross-study conflict resolution. No generated explanation
is declared wholly correct merely because its single relation label agrees with the public label.

## Validation and publication

A fresh Windows Python 3.12 environment installed the lightweight requirements and the project
without model caches or a copied `.env`. All six new medical records and all three workflow examples
replay there. Browser checks exercised source highlighting, checker disagreements, the final results
table, JSON downloads and unchanged Research → Audit transfer of the answer and all eight sources.
The transfer made no inference call; downloaded record fingerprints match the saved artifacts.

The Python suite passes 244 tests; the two existing frontend tests, production frontend build,
source Ruff checks, historical saved-report recomputation and 0.7.0 wheel build pass. A 430px browser
view has no horizontal overflow. These checks establish the exercised functionality, not clinical
reliability or a guarantee for every platform.

Source and notes are distributed on `main` and the fixed
[`v0.7.0` tag](https://github.com/lijingshan-6/medrag-agent/tree/v0.7.0).
This milestone does not require a separate GitHub Release page.

The web service remains a local research showcase. It does not inherit the separate MCP
authentication layer. Third-party data/model licenses remain distinct from the project's code
license; full model weights and upstream corpora are not committed.
