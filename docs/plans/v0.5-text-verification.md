# v0.5 文本审计实施计划

开始：2026-09-24。分支：`feature/veritasmed-audit-v0.5`。

发布收敛：2026-09-26，交付范围为可回放、可定位、可测量的文本审计研究版本。
真实医学 Ask → Audit 与无密钥回放见 [医学演示](../medical-demo.md)；
版本入口见 [v0.5.0](../releases/v0.5.0.md)。原始实验记录按发生时间保留。
技术决定以 [研究路线](../verification-roadmap.md) 为准；v0.4 标签与原始评测保持不变。

## 第一阶段：固定证据，建立可运行与可测量的最小链路

- [x] 写入路线、能力边界、数据来源与比较原则。
- [x] 独立输入/输出结构：claim、完整摘要、关系、句子 ID、原文范围与内容哈希。
- [x] SciFact 下载与适配：记录档案哈希、原始划分、官方标签来源、替代 rationale。
- [x] 预先固定 30 条试跑：仅选官方 train，支持/反驳/信息不足各 10 条；按固定种子排序。
      不与官方 dev 的已知引用/证据文献重合，同一 claim 与文献不重复入选。
- [x] 直接 Flash 基线，最多 3 个请求；完整摘要输入，核查器不读取答案标签。
- [x] 保存全部结果与失败；离线重算指标，记录标签分歧，不据 30 条试跑声明可靠性。
- [x] 只针对数据泄漏、原文定位、标签转换和评分边界做必要离线用例。

30 条是已标注公开数据的工程试跑，不是最终统计样本量。不得用结果重新挑选这 30 条。
规则、提示词或设置改变后另建目录；小规模试跑用于开发，不能重复包装成独立验证。
先固定数据及提示词，再调用模型；接口故障原样保存，后续恢复另留运行记录。

## 第二阶段：建立核查对照与诊断能力

- [x] 明确文本判断与领域知识的边界；保留公开基准原始标签和分歧，写入标注规范 v1。
- [x] 新运行保存全部流式模型标识与 usage；6 次诊断和 144 次对照返回标识一致。
- 已知外部限制：历史不同模型标识的路由原因未确认，底层身份不能仅由响应字段认证；不作为发布已解决事项。
- [x] 建立 12 文献组、48 条有原文锚点与构造说明的开发诊断样本。
- [x] 接入结构化方案，完成同输入的三方案比较、字段提示消融和聚合消融。
- [x] 原文定位完整性与语义分数分开报告；本批没有发现额外字段提示或聚合的准确率收益。
- 后移至 v0.6：接入专用核查模型，先统一支持/非支持与三分类任务的比较口径。
- [x] 增加自然回答人工标注及复合 claim，先明确标签映射与来源分组，不继续依赖简单构造题评分。
- 后移至 v0.6：固定正式开发、校准、评估划分和运行预算，再扩大样本；60 个 test 来源继续保留。

## 第三阶段：审计产品与完整链路

- [x] 定义 API 审计记录；界面逐条展开原文，答案与来源双向定位。
- [x] 接入 claim 提取并测其遗漏，不只审计生成器自报的 claims。
- [x] 展示未核查、关系判定、执行失败与不确定性；暂不提供未经校准的百分比。
- 后移至 v0.7：与强模型自行调用同样工具作固定预算对照，评估检索与修复收益。
- [x] 补真实论文原文的 Ask → Audit、无密钥保存记录回放、来源许可和发布说明。

这些后续研究没有被标成已完成。v0.5 不声称审计已经可靠或 Agent 优于强模型；
将产品可追溯性与可靠性实验分开，符合 [版本路线](../verification-roadmap.md)。

## 工作记录

### 2026-09-24：启动

已从已发布 v0.4 创建开发分支。现有 `RAG FrontEnd/` 与 ZIP 是用户文件，本阶段不修改。
从 SciFact 官方 README 指定地址取得原始数据；下载和外部语料保存在忽略的本地缓存。
公开数据适配与独立核查模块不改变 v0.4 生产回答路径。

后续每轮结果追加在此处，运行目录与完整失败列表写入专门实验报告。

### 2026-09-24：第一阶段已完成

新增独立核查模块、下载/适配/试跑/离线评分/逐条原文查看脚本；10 个相关离线用例通过。
30 条真实请求全部返回有效结果，与 SciFact 标签一致 25/30，五条分歧完整保留。
19 条有依据的输出均可重建原文位置；这不代表语义支持正确。

同时记录两项研究限制：现成基准存在别名/推理与严格文本任务的边界差异；网关有一次返回
不同的模型标识，且只有一次返回 usage。下一阶段先明确这两项，避免把分数变化误归因于 Agent。
详见 [试跑报告](../reports/verification-v0.5-pilot.md)，工件为
`data/verification/scifact_pilot/run01_flash_direct/`。本阶段没有发布 v0.5 或修改 v0.4 标签。

### 2026-09-24：受控诊断与首次消融完成

详见 [第二轮报告](../reports/verification-v0.5-diagnostics.md)、[标注边界](../verification-label-policy.md)
及 [网关观测](../verification-gateway-observations.md)。工件位于 `data/verification/controlled_v1/run01/`。

三种方案均为 48/48；结构化方案没有改进准确率，API 报告总 token 是直接 Flash 的 1.71 倍。
去掉字段提示、去掉程序聚合也没有降低本批分数。继续以 direct 作主基线，结构化模式保留研究用途。
这些是 12 个来源组上的明确事实/受控变更诊断，全部是开发数据，不是专家黄金集或临床可靠性证明。

14 个相关离线用例通过，144 次真实调用完成，指标可离线重算；原文视图可逐条追溯到原摘要句子编号。
下一轮优先引入人工标注的自然回答与复合陈述，再接专用核查器，最后接入真实审计面板。

### 2026-09-24：执行顺序调整

采用 [整段回答协议](v0.5-answer-audit.md)：自然回答研究与最小真实面板同时推进。
已实现 direct / split 两条整段审计路径、独立 HTTP API、原文联动和保存记录回放。
RAGTruth 只用官方 train 中的 24 个不同来源；错误分母包含未提取和未核查部分。
研究结果和全部分歧见 [本轮报告](../reports/verification-v0.5-answer-audit.md)，启动见
[面板指南](../audit-demo.md)。专用模型、概率校准、预留集评估和工具调用对照仍未完成。

### 2026-09-24：语境 / 元文本实验与 Ask → Audit 完成

按 [本轮计划](v0.5-context-audit.md)完成 126 次 Flash 调用，原 Direct 与 scorer 不变，
24 个新来源作成对对照，6 份固定答案重复。面板接通真实 Ask，保留原回答、全部证据及引用映射。
数值定位指标有改善，但存在警报粒度带来的命中和 3 份部分失败；继续保留 Direct 默认。
详见 [本轮报告](../reports/verification-v0.5-context-audit.md)。下一步先改进确定性定位与错误语义评测，
再扩大方法对照，未提前消耗预留测试集。

### 2026-09-24：具体错误与确定性定位完成

按 [本轮计划](v0.5-specific-error-audit.md)完成 33 处公开错误的 AI 开发诊断，明确不是专家 gold；
新增 quote-v2 唯一精确引文定位。126 份旧输出只换定位程序可恢复 2 份失败，原历史保留。
新 8 来源上的 36 次 Flash 调用全部完成，整段和固定目标任务分开，重复出现判断波动。
没有证据升级语义核查默认方法，Direct 保持默认；下一轮研究组合主张与判定稳定性。
见 [结果与限制](../reports/verification-v0.5-specific-errors.md)。60 个预留来源未用，v0.5 未发布。
