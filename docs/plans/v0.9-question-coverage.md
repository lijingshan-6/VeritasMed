# v0.9 研究计划：回答有依据，还要回答完整

[English](../en/plans/v0.9-question-coverage.md) | **简体中文**

状态：2026-09-27 设计确定；尚未下载新题集、开放最终区或运行模型比较。
默认保持 Flash / Direct。本计划接续 v0.8，不修改已发布 tag 或历史结果。

## 1. 本轮要回答的问题

**在同一问题、回答和来源下，显式记录用户要求，能否比一次直接模型审阅更少漏掉未回答的子问题，
同时不过度要求澄清、不把写作约束误判为文献缺口？**

目前逐条 claim 审计主要回答“写出来的话有没有来源支持”。它看不到未写出来的要求，
因而一份回答可以每句都通过，却没有完成任务。v0.8 的实际医学会话留下了三个开发反例：

| 已见失败 | 下一步需要识别什么 | 不应得出的结论 |
|---|---|---|
| 两篇论文之后问“它”，未澄清而回答两篇时长 | 指代是否唯一；不唯一就询问所指论文 | 不能靠最近一条强行指定对象 |
| “不要比较疗效”被当作证据缺口 | 用户的表达限制与需证据的子问题分开 | 遵守限制不是证据不足 |
| 回答三小时血糖，却漏掉是否有五年死亡率证据 | 每个明确子问题都有答案或明确的来源范围内缺口 | claim 通过不能自动标记整个问题已解决 |

这三例只做开发回归，不能成为独立最终成绩。前轮结果和具体限制见
[研究总览](../research-overview.md)与 [v0.8 报告](../reports/verification-v0.8-report.md)。

## 2. 要实现的产品形态

Ask 仍是主入口，Audit 仍在当前答案内。新增一块“问题完成情况”，与“陈述的来源支持”并列：

- 逐项列出用户明确要求，点击定位到**原问题**，再到答案对应句与已有来源。
- 分别显示“已回应”“明确说明当前来源不足”“尚未回应”“需要澄清”“检查未完成”。
- 写作限制单列，例如不比较疗效；不把它计作待检索的临床终点。
- “已回应”只说明覆盖了该要求。是否正确、是否有证据仍看该句的 Direct 审计。
- 默认保留原答。用户可以看到漏项后追问；本版不让新检查器自动改写答案。

不显示整体可信度百分比，不增加跨论文冲突裁决或临床适用性等级。
不把两个面板的状态平均成一个总分。全部检查绑定同一个答案版本和输入指纹。

## 3. 最小技术路线

新增独立 `question_coverage` 模块，先以保存输入离线运行，再接进网页。
不要在旧 `nodes` 中继续堆关键词补丁，也不修改冻结的 Direct / Atomic 推理文件。

```text
原问题 + 用户选中的有界上下文
  → 请求项提取（问题原文锚点、所指来源、事实问题 / 写作限制）
  → 保留歧义 / 等待澄清，或获得明确请求项
原回答 + 完整的所给来源 + 请求项
  → 每项答案定位 / 明确缺口 / 漏答 / 未完成
原有 Direct audit
  → 另列每句的来源支持，不替 coverage 作判断
```

拟定数据对象：`RequestItem(id, question_spans, kind, referent, status)` 和
`CoverageItem(request_id, answer_spans, source_ids, disposition, reason)`。
原问题原文保持不变；生成的请求项必须能回到原句，未知锚点不进入有效完成项。
来源未报告某结局的措辞限定为“所给文本未建立”，不能声称整个医学界没有证据。

复合要求拆分与指代识别本身也可能错，因此保留提取结果、被遗漏原问题片段、失败和原始回复。
机械锚点只检查位置；不得将其当作请求项语义提取正确的证明。

## 4. 数据：外部标签与构造诊断分开

没有临床专家，不以本系统自审或模型投票补出“医学 gold”。优先调查 **QASPER**：
问题和答案由不同的 NLP 从业者提供，附支持证据；它属于论文问答，领域不是临床医学。
[原论文](https://aclanthology.org/2021.naacl-main.365/)和
[Ai2 数据卡](https://huggingface.co/datasets/allenai/qasper)是来源，数据卡标注 CC BY 4.0。
这使它适合调查来源范围内的可回答性，**不意味着它已经标好了本项目的漏答审计任务**。

| 数据层 | 内容与参照 | 用途与限制 |
|---|---|---|
| A：原始外部任务 | 保持 QASPER 原问题、全文、人工答案/证据及 unanswerable 标签 | 检查可回答性与官方回答/证据指标；不能把 Answer F1 当漏答检查器准确率 |
| B：有操作记录的诊断 | 同一论文的两个明确问题、原有抽取式参照；构造完整回答与指定漏项等配对 | 测已知删除操作和请求覆盖；合成标签，不能宣称自然回答泛化 |
| C：真实医学应用 | 三个已见会话失败，加新的来源可追溯演示 | 检查产品迁移和失败类型；AI 阅读仅作诊断，不进入外部正确率 |

P0 只先检查最多 10 篇官方 train 文献，其 ID 全部记录为已曝光。核对原始字段、许可、
段落定位、多标注分歧、表格依赖、无法回答但又含答案等互相矛盾的记录。
作者仓库曾有 [标签字段问题讨论](https://github.com/allenai/qasper-led-baseline/issues/17)，
因此不能默认公开人工标签没有错误。保留全部原标注；主分析资格在看模型输出前决定。

本次设计时官方数据页自动展示了十篇 train 文献的部分内容，已经视为曝光：
`1909.00694`、`2003.07723`、`1705.09665`、`1908.06606`、`1811.00942`、`1805.02400`、
`1907.05664`、`1910.14497`、`1912.02481`、`1810.04528`。上述 issue 还显示三个 dev question ID：
`a5e49cdb91d9fd0ca625cc1ede236d3d4672403c`、`6a633811019e9323dc8549ad540550d27aa6d972`、
`a8c862d8c5da3f060eedf3395a3d0a97fd8a12d8`。P0 必须将这些问题所在整篇论文排除最终区。
尚未下载数据、读 test 或发起模型调用；不能把网页预览称作完全未见。

后续规模目标为 **30 篇开发论文、60 篇冻结评估论文**，来自官方 train / validation，
项目内按论文 ID、标题和正文哈希去重；官方 test 暂不触碰。已有阅读的 train 示例只入开发。
同篇的所有问题和变体必须同区。最终池按固定种子和预定分层选取，不按模型表现筛选。
这只叫“项目内冻结评估”，不声称公开数据没有进入供应商预训练。

诊断目标为每篇一对明确且不同的问题、四个版本：完整回应、只漏第一项、只漏第二项、
完整回应并加一个写作限制。漏项版本需确认保留句未顺带回答被删项；有歧义就列为不适用，
记录原因，不能用 AI 的肯定意见顶替。等义改写、代词歧义另做开发压力例，不混入机械主表。
原始参照不是经本系统生成的新“标准答案”；新组合也不能冒充原作者人工标注。

**数据可行性门槛：**在调用任何比较模型前，锁定数据 revision、筛选代码、文本视图、
纳排清单和实际分母。目标不足时明确缩小成试验性报告，不借用旧最终题补数。
若无法获得可直接审阅的删除参照，本版只交付开发诊断与面板，不发布新的可靠性提升结论。
RAGTruth 60 个官方 test 来源继续保留；SciFact 已用最终题只作回归，不改名为新测试。

## 5. 比较什么，怎样避免把复杂性当效果

同 Flash、同来源文本、同输入上限、同配置；先固定输入审计，不引入检索质量的混淆。

| 实验臂 | 实现 | 回答的问题 |
|---|---|---|
| A Direct coverage | 单次直接提示模型检查漏答、约束和歧义，返回最小可比较状态 | 强模型直接审阅能做到多少？这是新 coverage 基线，区别于旧 Direct claim audit |
| B Structured coverage | 先提取有原问锚点的请求项，再逐项检查，最多两次调用 | 显式拆分是否有额外收益？ |
| C Two-pass direct | 两次调用；第二次直接复核第一次的漏项判断，不给结构化请求清单 | 收益是否只是多花一次模型调用？ |
| D Oracle requests（仅诊断） | 给 B 构造时已知的请求项，再检查同一回答 | 失败来自请求项提取还是匹配？含特权参照，不能当可部署胜者 |

三条可部署臂都获得同一原始输入。每臂每个输入输出上限总计 16,384 token；A 可一次用完，
B/C 每次最多 8,192。分别保留实际输入/输出/推理用量、调用次数和延迟；相同上限不等于
相同计算量。P0 若发现某端点不能按此请求，必须在开发比较之前修订协议，不能为某臂单独放宽。
并发最多三，仅为运行设置，不增添服务架构。畸形输出/超时保留为失败，不择优重试。

开发阶段允许修改一次候选并保留前后全部运行；最终只运行冻结的 A/B/C，各项一次。
提前选定六个开发输入，每臂三次重复，报告不一致，不挑选最佳回复。D 不进入最终优胜比较。
正式最终表开放后，不再依据它修改候选并重跑同一批当新成绩。

## 6. 首要指标与升级条件

**首要指标是错误的“完整回应”放行率**：已知漏项版本中，被判全部要求已回应的比例。
同时报告漏项检出率、完整参照的正确接受率、写作限制误报率、有效执行率和全部原始计数。
执行失败单列并计入全计划分母；同时报完成条件下的指标，避免通过大量弃权显得低风险。
请求项提取 recall / precision 只对构造时已知请求项报告；不以字符覆盖率代替语义完整性。

A 层另报原始可回答性混淆矩阵，以及遵循官方多参照规则的 Answer / Evidence F1；
B 层漏答诊断和 C 层医学观察分表。它们不能合并成“系统准确率”。
按论文组配对重采样给 95% 描述区间，同篇所有变体一起采样，预先固定种子和 10,000 次重复。

启用 B 为默认 coverage 的必要条件：相对 A 和 C，冻结诊断中错误放行率下降的区间上界均低于零；
完整参照正确接受率差的区间下界不低于 −5 个百分点；有效执行率至少 95%。
这是项目工程取舍，不是临床安全标准。失败/区间太宽就保持 A 或保持实验性开关，并发布负结果。
即便通过，也只支持“在本次有操作记录的诊断中改善”，不能声称自然医学审计已可靠。

歧义澄清暂不设通用准确率：先修已见失败，保留需澄清与无需澄清的对照开发例、额外提问负担。
没有新独立会话标签，就不将手写上下文题的满分当作多轮泛化证据。

## 7. 实施顺序与交付

| 阶段 | 做什么 | 完成时应看得到什么 |
|---|---|---|
| P0 数据可行性 | 小范围 train 阅读、许可证/来源/暴露/标签分歧盘点 | 数据卡、纳排规则、实际可用数量；明确可做主比较还是仅试验 |
| P1 最小离线实现 | 请求项与覆盖模型；A/B/C/D；先接三个已见失败 | 可读逐项 JSON、原问/原答定位；一份共享输入能独立重放 |
| P2 开发与一次修订 | 30 篇目标、故障归因、六例重复、锁定提示与计分 | 所有开发尝试和淘汰理由；不拿新绿勾当改进证据 |
| P3 冻结比较 | 60 篇目标；A/B/C 同时保存，不用 D 评可部署优势 | 全部原始结果、错误放行/接受/执行/成本表、来源组区间及负例 |
| P4 产品收敛 | 把 coverage 接进所选答案版本，保留原审计；更新真实回放 | 无密钥可看漏答与澄清示例；一篇可重算研究报告与版本说明 |

## 8. 后续为什么仍然需要 Agent 研究

本版只检验“请求清单”这一处结构是否有价值，不能回答整个 Agent 是否更好。
如果它可用，下一版再比较“检查后一次定向补答”与“强模型直接重答”，保留原答，
用独立参照评修复收益和新引入错误。之后才扩大到开放检索和原生工具自主流程，固定同工具、
同信息权限与预算；如供应商不支持原生工具，应明确适配限制。

临床适用性、因果设计等级、跨论文可比性和冲突裁决继续独立立项。新的外部语义核查数据
仍需寻找；QASPER 补的是问题/证据参照，不填平这项医学缺口。论文写作应容许结论是
“简单模型已足够”或“结构增加了误报”，而不是预设必须证明自己的 Agent 更优。
