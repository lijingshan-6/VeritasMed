# 技术路线：先让审计有依据，再让它指导回答

[English](en/verification-roadmap.md) | **简体中文**

最终产品是一套可追问的文献工作台：问题、答案版本、每条陈述、原文和审计记录彼此可定位；
没有完成核查和确实缺证据的地方同样可见。研究目标是测出哪些检查可靠、何时失效，以及
什么结构确实比同模型直接调用更有价值。临床适用性和跨论文可比性单独研究。

## 当前在哪一步

v0.8 已有持久会话、真实论文演示、逐版本审计和可重算记录。当前最重要的负结果是：
规定的研究流程尚未显示优势，限定语定位改进也没有建立新的语义可靠性结论。
具体数字只维护在 [研究总览](research-overview.md)及[版本报告](reports/README.md)。

三条执行路径必须分清：完整 Ask 图生成并内部检查答案；独立 Audit 检查已保存回答；
Research 比较给定论文范围内的工具流程。后两者的成绩不能写成完整 Ask 的端到端成绩。

## 下一个版本：v0.9 问题覆盖审计

集中解决“每句话有出处，回答仍漏掉问题”的漏洞。增加原问题请求项、答案回应和缺口之间
的对应关系，与现有 claim 支持关系分开显示。优先处理漏答、写作限制误报和指代未澄清。

[唯一实施计划](plans/v0.9-question-coverage.md)明确了数据可行性、Direct / 结构化 /
同调用次数对照、提取上限诊断、错误放行与正确接受指标、冻结步骤和不升级条件。
先核实外部数据能支持什么；没有合格参照，就交付开发诊断，不能填一张可靠性漂亮表格。

## 后续阶段，以证据为条件

| 阶段 | 要证明什么 | 前提 |
|---|---|---|
| 检查指导一次定向补答 | 修正已识别漏项是否优于强模型直接重答，是否引入新错 | coverage 有明确可用范围；原答、修订和外部参照都保留 |
| 开放检索与自主工具比较 | 固定信息权限和预算后，某处结构是否有独立收益 | 数据和工具协议可比；不把旧应用 JSON 适配当原生工具能力上限 |
| 自然医学语义可靠性 | 对完整自然回答的误报、漏报、错误接受和必要弃权 | 新的可追溯外部标签；不能用 AI 投票或旧最终集补足 |
| 临床证据等级 / 文献冲突 | 适用人群、因果设计和跨研究比较是否成立 | 专门方法学标准及合格标注，不能从文本蕴含分数直接推出 |

这些不是已经承诺完成的 v1.0 功能。没有研究收益的结构不升级默认；允许简单方法获胜。
Flash / Direct 继续使用，不开启例行 Pro 裁判，不展示未经校准的可信度百分比。

研究协议及历史失败见 [报告目录](reports/README.md)，运行步骤见 [复现指南](research-reproduction.md)。
