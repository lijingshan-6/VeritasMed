# v0.7 的研究范围与默认策略

决定日期：2026-09-26。制定和分区时即确定 v0.7 查询范围，未根据最终成绩挑选任务。
承接 [v0.6 计划](../plans/v0.6-audit-reliability.md) 与 [v0.7 协议](../plans/v0.7-agent-comparison.md)。

## 本轮可回答的问题

使用同一个 Flash 配置、固定八篇候选摘要、相同 search/read/verify 工具及上限，比较：
一次读取全部摘要、自主调用工具、程序安排检索和核查。在“指定论文是否支持给定 claim”上，
公开 SciFact 标签提供不依赖本系统核查器的参照。

本轮独立开发/最终查询各 20/40 个来源组，均在 v0.6 其他分区之前留出。目标标题公开、
正确 document ID 和关系标签不进入模型输入。工具内核查也收费并计入模型调用预算。
原草稿、核查分歧、无效输出与预算失败都保留。

## 为什么没有立即接管整个 Ask 流程

早期路线设想 v0.7 用审计指导补检索和自动修复，然后比较完整 Agent。本轮没有将这一设想
悄悄算作已完成：现有公开标签更适合指定文献的文本关系，不能给开放医学问题的完整答案独立打分。
构造诊断也不能代替临床 gold。

v0.6 开发已发现规范化子事实丢失季度分母、重复事实和对原文明确事实的不足判断。校准区
未找到符合预定风险/样本量条件的阈值。若把这些核查意见强制用于修复，会有把正确原答改坏的风险。
因此本轮工作流只在分歧时保留判断，不让核查器修改原答案再给自己打高分。

这是一项明确的范围调整：**交付受限但有外部标签的工作流对照；开放补检索、自动修复与历史
完整 Ask graph 的比较后移**。不能将本轮结果宣传成已证明“为什么整个医学 Agent 胜过强模型”。
研究是否支持升级，由预定指标决定，发布里程碑本身不要求得到正结果。

## 默认与最终数据

- Flash 基线继续；没有 Pro 回退或 Pro 裁判。
- Direct 仍是审计默认。原子方法与 MiniCheck 是可检查的研究选项。
- 没有合格校准规则就不发布可信度百分比；模型分歧提示复核，不按投票形成 gold。
- 固定目标最终区与医学转移区按已冻结方法执行，不以最终输出反复改提示。
- 60 个 RAGTruth test 来源继续保留：尚未解决整段语义评分，不为“完成版本”提前使用。
- v0.6 研究与 v0.7 功能在一个 v0.7.0 源码里程碑内交付；不补造 v0.6.0 已发布历史。

后续需要新建“题目不提供目标论文、必须补找证据”的独立任务与评分契约，并测修复是否保留
原有正确内容、是否新增错误。仅重复当前 40 题、增加调用次数或更换更强模型不能代替这一证据。
