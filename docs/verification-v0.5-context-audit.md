# v0.5：语境与元文本开发实验

2026-09-24。126 次预定调用已完成。**保留 Direct 为默认，Context + meta 作为可选实验策略。**
新来源的定位指标有改善，但新增命中受警报范围变化影响，且新增结构引入引用失败；
本轮没有证明语义核查更可靠，也没有证明 Agent 优于强模型自主调用工具。

## 本轮实际改了什么

原始 Direct 与 scorer 未改动。新增三个单次调用策略：Context only 提供精确段落语境与
归因/时态等解释要求，Meta only 显式分流当前回答自身的呈现说明，Context + meta 同时启用。
每条 claim 仍绑定回答原文，依据仍绑定来源原文；段落边界由程序产生，模型不能自行改写。
精确绑定不等于正确理解。语境只用于理解回答，不能作为支持回答的证据。

分流的文字保留在 `meta_text`，既不算 Supported，也不从人工错误分母删除。
额外统计 meta 与 gold 相交的范围/字符，防止通过多排除内容制造高分。
字数说明只附带完整回答按空白切分的计数，没有假定作者想用哪种自然语言字数规则。

产品上，完整应用的 Ask 工具栏可以把原回答和全部返回的来源片段送入 Audit 输入页。
它保留原问题、会话及 citation/chunk 映射，需要主动执行审计，不自动改写答案。
来源数上限从旧独立输入的 4 提高至 40，仍限制来源总字符数 80,000，不静默截断。
原 4-source 基准输入类与历史 runner 不变；新的服务请求结构单独定义。

## 数据、对照和边界

[调用前计划](plans/v0.5-context-audit.md)与[固定工件](../data/verification/context_v1/README.md)保留了
样本、原标签、提示词、代码、调用顺序和配置。依然是 Flash、高推理档、每次最多 32,768 输出 token，
最多 3 个请求，无 Pro 回退。响应中的模型字段只记录网关报告值，不能认证底层权重。

| 数据 | 样本 | 比较 | 新调用 |
|---|---:|---|---:|
| 回归 | 原 24 回答 / 24 来源，15 个原错误范围 | 三个新增策略；Direct 复用上轮 | 72 |
| 新开发 | 新 24 回答 / 24 来源，18 个原错误范围 | Direct vs Context + meta，同批次交错 | 48 |
| 重复 | 从新组预选 6 回答，3 份有标错、3 份无标错 | Context + meta 第二次独立调用 | 6 |

两个开发组均按 12 份有错误标注 + 12 份无错误标注抽取，不能据此估计自然问题发生率。
新组 18 个原始标签包含 14 个 `Evident Baseless Info`、2 个 `Subtle Baseless Info`、
2 个 `Evident Conflict`；其中 1 个带 `implicit_true`，仍按来源未支持计分。
这不是均衡的三分类数据，更不能用它评估医学证据等级或跨文献冲突识别。
新组排除全部旧来源及全部官方 test 来源；预留的 60 个 test 来源继续未执行。
这是公开通用领域训练数据，存在预训练暴露可能，不是新建专家黄金集或临床可靠性评估。
旧组 Direct 是跨批次对照；消融也只有一次运行，不能把每处差异都确定归因于某条提示。

## 差异台账与解释原则

[完整旧台账](../data/verification/context_v1/run01/prior_disagreement_ledger.md)枚举了 104 条警报：
72 条没有和 gold 相交、32 条相交；另有 2 次完全漏检、3 次低于半范围覆盖事件。
同一个错误可以出现在两种方法中；事件数不能当成独立题数。
无交集只表示与参考标签分歧，不能自动判为专家确认的误报。

- `3758`：旧 Split 把归因下的指控抽成裸断言，旧 Direct 本来没有这个错误。本轮单次调用保留归因，不能据此声称新 context 字段优于 Direct。Context 还增加一处关于过去/将来时态的警报，而原 gold 未标错；原文、警报和分歧都保留。
- `4624`：Context only 仍把“107 words”视作缺乏来源支持，Context + meta 将它单列。但旧 Direct 也没有这条多余警报，不能将相对 Split 的改善冒充相对 Direct 的提升。
- `5175`：旧方法都指出人数 26 与来源合计 27 不符，但警报短语小于原标注的整句，影响半范围指标。这是定位粒度差异，不能通过修改 gold 来解决。

其他回答的原标签、警报和判断理由见[全部逐题对照](../data/verification/context_v1/run01/paired_cases.md)。所有开发解释不回写公开标签。

已保留的引用错误包括：回归 `2978 / Context only` 有一条来源引文找不到；
`4492 / Context + meta` 把字符起点 39 填成 quote 的第 39 次出现，导致元文本定位失败。
未自动改写引用或索引；有效事实判断仍逐条保留，整次运行显示 `partial_error`。
新开发 `736 / Context + meta` 另有 6 条 claim 选错语境 ID、1 条元文本出现序号错误。
其重复调用正常返回；第一次失败保留，不能用第二次覆盖。

## 结果

运行 UTC 14:21:44–15:06:59，126 次均返回可解析 JSON，123 份完整绑定、3 份部分失败。
126/126 有 usage，全部响应模型字段为 `deepseek-v4.1-flash`；网关报告总计 **2,185,872 token**。
这些 token 是本轮新调用之和，不包含复用的旧 Direct。原 scorer、样本、提示词及剩余调用未因中途结果改变。

### 新来源：同批次成对比较

| 指标 | Direct | Context + meta |
|---|---:|---:|
| 完整绑定的回答审计 | 24/24 | 23/24 |
| 错误范围：任意交集 | 16/18 | 17/18 |
| 错误范围：至少覆盖一半非空白字符 | 13/18 | 15/18 |
| 无标错回答被报警 | 9/12 | 7/12 |
| 警报字符 precision / recall / F1 | 24.5% / 68.0% / 36.0% | 30.1% / 77.6% / 43.4% |
| 已报告 token | 427,641 | 460,306 |
| 回答耗时中位数 | 65.7 秒 | 68.4 秒 |

Context 的 token 为 Direct 的 1.076 倍。三项预登记的**数值效果条件均满足**，
但原计划只允许据此讨论升级，并不要求自动改默认。完整运行情况与下面的语义复盘另列，
没有事后把新条件伪装成原来的预登记指标。[机器可读决定依据](../data/verification/context_v1/run01/paired_effects.json)。

**为什么没有据此宣称变得更可靠：**

1. `699` 多出的 gold 命中是 `improvised explosive devices` 的缩写展开。Context 警报覆盖了
   包含该短语的更长句子，但理由指出的是 “key supplier / other organizations”，并未指出
   缩写展开这个原始错误。字符命中不能证明理解了 gold 所指的问题。
2. `5583` 的两个方法都质疑年份 `2023`。Direct 只标短语，Context 首次标整句，因而超过
   半范围阈值；重复又回到短语。原标注说明还涉及资格生效时间的范围，不能把变宽的警报
   当成新增语义错误检出。两个新增半范围命中都受到范围粒度影响。
3. 无标错回答减少警报的两个例子是 `718`、`736`。前者确实把回答自身的字数说明单列；
   后者首次语境绑定失败，不能将“没有有效警报”算作成功确认其余事实。
   Context 的 7/12 包含这一未完整完成的样本；在其余 11 份无标错回答中，仍有 7 份报警。
4. 旧组 `4990` 的原错误在三个新方法下仍全部漏检；新组 `1778` 的一处 gold 也仍未命中。

### 旧组消融与重复

| 回归策略 | 半范围命中 | 无标错回答警报 | 字符 F1 | 完整审计 |
|---|---:|---:|---:|---:|
| 原 Direct（上轮） | 12/15 | 9/12 | 38.9% | 24/24 |
| Context only | 11/15 | 9/12 | 37.6% | 23/24 |
| Meta only | 12/15 | 8/12 | 39.4% | 24/24 |
| Context + meta | 12/15 | 8/12 | 37.1% | 23/24 |

单独加入语境没有显示整体收益；元文本分流在这批上略好，但旧组 Direct 是跨批次结果，
每种消融只有一次，不能凭这些差异宣布独立机制已被证实。

6 份重复的回答级“有无警报”与首轮一致，但这掩盖了位置波动：3 份有错误的回答，
警报字符 Jaccard 为 0.225、0.696、0.700；`5583` 由整句变短语正是例子。
`736` 首轮有结构失败，不将它表面为 1 的 Jaccard 计作可靠的稳定性证据；
其余完整配对也只能反映这个小样本的表现。完整指标见[数表](../data/verification/context_v1/run01/results.md)。

所有新策略的**有效**元文本路由与原 gold 的字符交集均为 0；无效引用另计。
这说明没有通过删除本批 gold 来提高分数，不能证明分流器在其他输入上永不误排事实。

### 本轮决定与下一步

- 产品保留 Direct 默认，新模式供研究和查看语境；不接入自动修复。
- 下轮优先取消模型重复填写可由程序计算的段落/出现位置，显式记录恢复或不确定状态；
  另设版本及对照，不能回填修改本轮失败。
- 完善评测对“命中了字符”与“指出了那个具体错误”的区分。可以利用公开标注的原始说明
  制作开发诊断，但 AI 整理/复核仍不冒充独立专家 gold，也不让同一个核查器充当自己的裁判。
- 方法和评分边界稳定后再使用预留集；60 个官方 test 来源本轮继续未执行。

## 演示与复现

按[面板指南](audit-demo.md)启动即可回放已保存的 Context 结果，无需新模型调用。
展开 claim 的 **Answer context** 查看归因所在段落；引导语和字数说明在 **Presentation text**。
导出 JSON 保留输入、完整语境、原文位置、分流与实际调用。新输入服务不落盘，主动导出后才有本地记录。

```sh
python scripts/verification/answer_benchmark.py download
python scripts/verification/context_benchmark.py report
python scripts/verification/context_report.py
```

最终两条命令不调用模型；逐题报告要求全部预定尝试已保存。既有 v0.4/v0.5 历史工件保持原样。
本轮未加入自动修复、医学分级、跨文献裁决或未经校准的“可信度百分比”，也未发布 v0.5 标签。
