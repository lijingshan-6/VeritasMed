# v0.7.1 — Ask first, audit within the answer

2026-09-27. A product correction to v0.7.0; its research records and original tag remain unchanged.

## What changed

The lightweight audit/research launcher hid Ask, while the README promoted that launcher as the
main entry. The complete question-answering application still existed, but the product appeared
to have abandoned it. This patch restores the intended relationship:

**Ask → answer and sources → audit this answer → continue asking.**

- Ask's **Audit** button opens the existing claim/source panel inside the current question workspace.
  The original question, answer, source passages and bottom composer remain available.
- **Back to answer** closes the panel. Reopening it retains that answer's audit state while the
  Ask page remains mounted. A new question clears the previous active audit context.
- Audit lab and Research remain supporting workspaces. Audit lab navigation no longer reloads
  the entire application, so the current Ask answer survives a visit to the lab and return.
- The lightweight workspace exposes **Ask ↗**, identifies its limited scope and links to full setup.
- The README leads with Ask, its actual medical answer screenshot and full-flow instructions.
  Package/API versions are 0.7.1; no dependencies or research model settings changed.

## Use it

Follow the [README](../../README.md). With the complete environment and configured Flash endpoint:

```sh
python scripts/run_demo.py --medical
```

Open **http://127.0.0.1:5173/**. After a completed answer, choose **Audit**, then **Run audit**.
Opening the panel itself makes no model call. The separate lightweight replay remains
`python scripts/run_audit_demo.py` on 5174 and does not provide the retrieval backend.

## Boundaries and next version

This is an integration patch, not a claim that complete conversation memory is implemented.
The backend deliberately starts a fresh graph state per question; the thread label is not
contextual memory. Full turn history, reload recovery and per-answer audit persistence are
planned in [v0.8](../plans/v0.8-conversation-and-audit.md). Current in-page audit state is not
durable across page refreshes or all navigation. Research conclusions and Direct's default
status are unchanged. No paid experiments were rerun for this patch.

Browser walkthroughs used the explicitly labelled authored Ask examples to exercise inline
audit, return/reopen, a subsequent question, and Audit lab → Ask without losing the answer.
The lightweight Ask link reaches the full application, whose backend was refreshed to current
code. Existing frontend tests and the production build pass. These are interaction checks,
not new medical performance measurements.
