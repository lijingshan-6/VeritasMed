# v0.7 实施协议：同模型、同工具的端到端比较

制定：2026-09-26。完成：2026-09-27，随 `v0.7.0` 交付。承接 v0.6。
两轮开发各 60 条、冻结最终 120 条记录全部保留。最终正确接受为 35/40、35/40、31/40，
错误接受同为 2/19；没有默认升级依据。见 [报告](../verification-v0.7-report.md) 与
[全部最终案例](../verification-v0.7-cases.md)。下文保留实施合同和开发期修订。

## 研究问题与范围

固定 Flash、文献库、搜索/读取/核查工具、每次调用设置和调用上限，比较自主工具循环与
明确安排检索、读取、回答、审计的工作流。另保留直接阅读全部候选文献的一次调用基线。
记录检索到的原文、回答、逐条审计、调用及错误，检验“本 Agent 的结构是否值得”。

这里首先比较可复现的**文献事实查询**：询问指定论文是否支持某陈述，候选库包含目标论文
和固定干扰文献。不是开放医学研究的总体评价；固定文献库避免实时搜索结果漂移。
查询包含论文标题而不提供目标 ID、答案标签或依据句。这让任务可唯一评分，同时保留搜索、
读取、选择证据和组织答案的步骤。不得将结果宣传成已证明临床问题上的 Agent 优越性。

## 输入与隔离

- SciFact 官方 train 中另留来源连通组：20 组开发、40 组最终比较，每组按固定 seed 选一个配对。
- 与 v0.5 已用来源、v0.6 固定目标/医学构造/校准/最终区互斥；正式数量由准备程序报告。
- 每题目标文献加 7 篇固定干扰文献；干扰来自开发可见语料且不同关联组，按 seed 选定。
- 标签只说明指定论文的支持关系；回答引用其他论文不能改变指定论文的 gold。
- 最终题在方法、提示和预算冻结后运行一次；不按最终结果修提示。公共数据预训练污染仍可能存在。

## 三臂与预算

1. `direct_reader`：一次调用读取全部 8 篇摘要并回答、选出逐字依据。
2. `autonomous_tools`：Flash 自主调用同一个 `search`、`read`、`verify` 工具接口，最后提交答案。
3. `structured_workflow`：程序安排 search → read → draft → verify，保留草稿与核查分歧，不自动修答案。

两种工具臂最多 6 次模型调用、8 次非模型工具调用。verify 的 Flash 调用计入相同总预算，
不得把工具内推理视为免费。每个输入/输出、调用序号、token、耗时和预算耗尽均写入 trace。
自主工具调用使用有校验的 JSON action 协议，明确记录为应用层工具协议，不冒充 provider 原生 tool_calls。
工具可见文献、参数限制及返回内容相同；结构化流程本身也使用公共工具实现。
公平不等于耗费相同，报告上限及实际消耗；一次调用臂用于展示更简单方案的表现与成本。

2026-09-27 开发修订：首轮自主臂 0/20 完成暴露 finish 包装与裸答案的冲突要求，以及
收到 JSON/DSML 混合回复的适配缺陷。最终题保持未运行，完整保留首轮 60 条后，明确 finish
指令并增加记录在案的格式归一化：只解释开头 JSON，对 DSML 后缀不执行、不作证据、不放入
模型历史；合法完整裸答案仅包装为 finish。读过文献、真实引句及六次预算要求不变。
三臂同一开发区完整第二轮后才冻结最终方法，不能用首轮协议失败证明 Agent 推理结构优越。

## 评分与默认决定

- 目标文献检索/读取覆盖、三分类与二分类、非支持被接受、正确支持召回。
- 无答案、无效 JSON、无效引用、预算耗尽分别计入全量分母，不能当作正确拒答。
- 引句精确匹配只证明位置；语义判断按公开标签评分，审计器自评另列。
- 按来源组配对差值与 95% bootstrap 区间；每臂完整原始记录、失败、成本保留。
- 默认改变沿用 v0.6 的错误接受改善和支持召回非劣标准；无证据则保持既有 Direct 审计默认。
- v0.6 的核查器自身仍会出错，v0.7 不能用它自评来宣布自己的答案正确。
