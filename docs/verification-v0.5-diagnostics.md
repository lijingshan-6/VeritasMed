# v0.5 第二轮：受控诊断、结构化核查与消融

2026-09-24。开发实验完成；v0.5 尚未发布。

## 结论与设计决定

**本轮没有发现结构化核查优于直接 Flash 的准确率证据。** 在 12 篇文献构造的 48 条诊断
样本上，三种方案都是 48/48，与构造标签完全一致。结构化方案消耗了更多 token，单条延迟也更高。

因此继续以直接 Flash 作为下一轮文本核查的主基线，结构化方案保留为研究选项。
当前证据不足以把逐项检查或程序聚合作为必需的生产路径。
原文定位、版本记录和可复查输出仍有产品价值；这不能被当成额外语义判断收益。

本批存在明显的高分上限：事实明确、变更局部、来源视图受控，并且只有 12 个独立文献组。
全部通过说明这些基本诊断未暴露失败，不能说明核查器在自然回答上可靠，更不能证明 Agent 优于强模型自行使用工具。

## 实际实现

- [文本标注边界 v1](verification-label-policy.md)：支持、反驳、信息不足；实体/条件一致；明确外部知识与精确换算边界。
- [48 条诊断样本与说明](../data/verification/controlled_v1/README.md)：原句锚点、单点修改、等价依据、证据删除与等量控制。
- 独立结构化核查器：保存每项判断及模型最终判断，程序聚合；保留不使用聚合的同次输出消融。
- 原始流式 Flash 适配器：保存流中的全部模型标识、用量及完成状态，不保存隐藏推理内容。
- 离线逐条查看：展示构造理由、当前视图、原摘要句子编号映射和三种方案的实际输出。
- 14 个相关离线用例通过；真实 144 次调用完成；保存指标已通过离线重算。

生产回答链路、v0.4 冻结工件及用户的前端 demo 文件未改动。本轮不涉及 GPU 推理。

## 数据定义：这是受控诊断，不是新增专家黄金集

12 篇来源均来自 SciFact train 的已知文献集合，避开官方 dev 文献与上一轮试跑文献。
每篇四条：正确事实、等价改写、单点矛盾、移除关键证据后信息不足。
共 24 条支持、12 条反驳、12 条信息不足。

覆盖人数与角色绑定、筛查/随机化分母、时间和质量单位换算、结局比例、原文明示统计限定、
治疗组、年龄区间、研究数/人数、日历事件、排除/保留人数、指定细胞背景下的方向。
这些是文本事实核对，不进行临床证据等级推断。

前三种变体移除与第四种相同数量的非必要句子作为控制。保留句子的顺序不变；
例如随机化人数同时从三处移除，包含可以把各组人数相加得到总数的句子。
全部构造规则及理由在调用前保存，调用过程中没有改题、改标签或调提示词。

标签来自 **原文锚点、明确构造规则与 AI 审阅**，并非新增独立专家标注。
样本经过策划，全部是已暴露的开发数据；等量删除不能消除所有人工构造线索。
原始 SciFact claim 的官方标签没有用于这些新 claim，也没有被更改。

## 实验条件与消融

| 方案 | 单次调用行为 | 聚合 |
|---|---|---|
| direct | 第一轮的直接核查提示词，返回关系和依据句 | 使用模型最终判断 |
| structured | 逐项判断，并提示检查对象、数值、单位、时间、比较和限定 | 任一矛盾优先，其次信息不足，否则支持 |
| structured_no_fields | 同样逐项格式，去掉显式字段核对提示 | 相同规则 |

三组使用相同 claim 和文本视图、同一 Flash 请求配置、每条一次逻辑调用和同样 token 上限。
同一 case 的三个方案在同一批次调用，批内顺序与 case 顺序预先打乱，最大并发 3。
没有 Pro、答案修复或根据得分追加重试。SDK 仍允许一次传输重试。

结构化方案的“不使用程序聚合”消融直接读取同一次模型输出的最终判断，不额外调用模型。
这能观察聚合有没有改判，不能证明模型逐项列表覆盖了 claim 的全部内容。
direct 与 structured 的比较同时改变提示词和输出格式；并非只隔离一个算法变量。

本轮统一使用原始流式 SDK；与前一轮 LangChain 适配器不同，不将两个数据集的分数当作模型提升趋势。
三个方案内部的传输实现相同。

## 全量结果

| 指标 | direct | structured | structured_no_fields |
|---|---:|---:|---:|
| 与构造标签一致 | 48/48 | 48/48 | 48/48 |
| 12 组内四条全对 | 12/12 | 12/12 | 12/12 |
| 正确/等价改写均判支持 | 12/12 | 12/12 | 12/12 |
| 移除证据后判信息不足 | 12/12 | 12/12 | 12/12 |
| 非支持样本错误接受 | 0/24 | 0/24 | 0/24 |
| 执行/格式/越界错误 | 0 | 0 | 0 |
| 有依据输出的定位重建 | 36/36 | 36/36 | 36/36 |
| 恰好匹配构造锚点句集合 | 36/36 | 28/36 | 29/36 |
| 平均单条耗时 | 3.45 秒 | 6.50 秒 | 5.22 秒 |
| 中位单条耗时 | 3.05 秒 | 5.67 秒 | 4.57 秒 |
| API 报告输入 token | 46,243 | 51,619 | 47,827 |
| API 报告输出 token | 11,813 | 47,703 | 34,146 |
| API 报告总 token | 58,056 | 99,322 | 81,973 |

整轮墙钟时间 320.61 秒。144/144 调用均返回 usage，原始流中的模型标识均为
`deepseek-v4.1-flash`。这是返回元数据的一致性，不是底层权重认证；历史差异原因仍未确认。
独立的 6 次原始流诊断及说明见 [网关观测](verification-gateway-observations.md)。

按本轮 API 报告总 token，structured 为 direct 的 1.71 倍，structured_no_fields 为 1.41 倍。
这些是用量，不是实际账单费用；单次运行和并发/缓存变化也限制延迟的可推广性。

structured 的 8 条、structured_no_fields 的 7 条锚点集合不完全一致，全部是包含原锚点并额外
选择了其他句子，没有缺失构造锚点。不能把这种集合差异直接称为语义失败。
逐项结构会汇总更多依据，这也解释了它为什么不一定给出最小句集。

两个结构化方案的程序聚合均没有改变任何一条模型最终标签。
去掉显式字段提示也没有降低本批分数。全部配对结果均为双方正确，无法估计非零准确率收益。
这两个消融结果只适用于本批，不证明这些机制在复杂材料中永远无效。

## 对后续工作的影响

1. **继续保留 direct 主基线。** 结构化模式保留作可解释输出与研究对照，不因为输出更长就视为更可靠。
2. **转向自然回答的人工标注与复合陈述。** 下一批同时考察部分支持、引用对象错配、限定遗漏、claim 提取遗漏。
   [RAGTruth 官方资料](https://github.com/ParticleMedia/RAGTruth)提供自然生成回答的人工错误范围标注，
   可以补充“指定来源是否支持回答”的测量；须先处理原始任务、`implicit_true`、质量标记及来源分组。
   它包含通用任务，不能直接作为医学可靠性的证明，也不能把词级标注未经适配直接当作三分类 claim 标签。
3. **接入专用核查器前先统一任务。** 二分类模型只能先比较支持/非支持，不能伪造反驳/不足的区分。
4. **正式比较先冻结新来源组。** 本批 12 组和上一轮 30 条都只作开发；新增开发、校准和保留评估
   必须按来源及相关变体分组，再决定样本规模和指标，不重复包装本批为独立测试。
5. **面板接入以真实记录为准。** 显示关系、依据、未核查与执行失败；校准前不提供可信度百分比。

专用核查模型、大规模保留评估、claim 提取及前端审计面板尚未完成。v0.5 尚未达到发布条件。
