### 本批实现

- 真实 Conversation → Turn → AnswerRevision → AuditRun 关系；会话 ID 不再充当虚假的历史。
- 选择任意历史答案后，来源、过程、Audit 跟随该版本。重生成同题追加版本，核查重跑追加记录。
- IndexedDB 保存完整原文来源与回答；刷新恢复。旧 ID 迁移为空记录；存储故障显示告警并保留导出。
- JSON 导入/导出带 schema、整体校验和、答案/来源 SHA-256；拒绝不一致的引用位置和来源替换。
- 中止、超时、失败归属于原请求，切换会话不把迟到响应写进另一个问题。
- 手工修改审计输入作为独立 edited experiment 留存；网络响应丢失标为 transport_error。
- 显式传入至多 6 轮 / 12,000 Unicode 字符的上下文，完整轮次选择，显示省略量。
- 后端新增 Flash 意图解析。用户原句逐字保留，指代说明单独附加；独立问题不继承历史范围，
  歧义/无效解析先澄清。graph 仍逐请求新建，旧回答不传入证据槽位。
- 记录解析原始输出、使用的历史 ID、耗时与供应商用量。该用量不冒充整个 Agent 总成本。

使用和边界见[对话指南](../../conversation-guide.md)。API/包版本号仍为已发布基线 0.7.1，
本批是 v0.8 开发进展；未创建 v0.8 tag 或发布说明。

### 先冻结的追问诊断

输入：[context-dev.json](../../../data/verification/v08/context-dev.json)。12 个开发者构造场景：
4 个明确指代（含一例澄清后继续）、4 个条件变更、4 个歧义或话题切换。中英双语。
输入历史是编写的意图片段，其中含明确标注的虚构研究/药物；不是 Agent 答案效果或专家医学黄金集。

固定检查项：解析模式、用户原句保留、指定指代出现、预先指定的过期范围不得进入附加检索上下文。
这种字符串/模式判据很有限，不证明所有语义正确，不作为独立最终集。没有在观察结果后改判据。

| 开发运行 | 原定判据通过 | 供应商 total_tokens 合计 | 解释 |
|---|---:|---:|---|
| [run-01](../../../data/verification/v08/context-run-01/summary.json) | 11/12 | 12,475 | context-05 提到了当前无糖尿病人群，也把旧“with type 2 diabetes”放进了参考上下文，触发范围判据 |
| [run-02](../../../data/verification/v08/context-run-02/summary.json) | 12/12 | 11,619 | 明确只保留当前范围、禁止复述被替换条件后重跑；开发复测，不是新保留集 |

两轮均为 `deepseek-v4.1-flash`（供应商标识），最多 3 个并行调用。没有 Pro 裁判或 best-of 投票。
每轮保存输入、提示、代码指纹、完整解析输出、用量；第一次的未通过结果保持原样。
context-05 的第一轮并非已经证明生成了错误医学答案：它识别了变化，但检索输入存在旧范围污染风险。

复现（必须指定新目录；不会覆盖已有运行）：

```sh
python scripts/verification/v08_context.py --output data/verification/v08/context-new-run
```

需先配置本地 `.env` 中的可用 Flash 服务。此命令调用模型；只测试意图解析，不运行检索或医学核查。
