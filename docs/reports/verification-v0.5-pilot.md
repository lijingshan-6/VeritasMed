# v0.5 文本核查：第一轮固定证据试跑

日期：2026-09-24。状态：开发试跑完成，v0.5 尚未发布。

## 这次实际完成了什么

已实现独立的 claim/摘要核查模块、SciFact 数据适配、确定性样本选择、Flash 调用、
原文句子绑定、离线评分和逐条查看命令。接口结构、句子越界、数据隔离、替代依据和
评分分母的 10 个离线用例通过。生产问答 graph 与 v0.4 冻结工件未改变。

本轮只测给定 claim 和给定完整摘要。没有接入检索、claim 自动提取、答案修复或审计前端，
也没有开始证据分级与跨文献冲突裁决。因此尚不能证明完整 Agent 比模型自行调用工具更好。

## 数据与运行条件

- [样本清单](../../data/verification/scifact_pilot/selection.json)：SciFact 官方 train 中各类 10 条，共 30 对。
- 原始 train 共 919 对；排除与官方 dev 的已知文献交叉后有 609 对候选，再按固定种子选择。
- 官方 dev 涉及 283 个已知文献 ID；所选 claim 的所有已知相关文献与它们不重合，入选 claim 间也不重复文献。
- 模型输入为完整摘要，而非参考答案中的正确依据句；参考标签仅用于采样和离线评分。
- 每条一次逻辑调用，最大并发 3；SDK 允许一次传输重试。无答案修复、无 Pro 回退。
- 请求模型 `DeepSeek-V4.1-Flash`，网关 `https://www.cun.ai/v1`，high reasoning，流式返回，最大 token 32768。
- [运行记录与代码哈希](../../data/verification/scifact_pilot/run01_flash_direct/run.json)、[全部原始输出](../../data/verification/scifact_pilot/run01_flash_direct/predictions.jsonl)、[机器指标](../../data/verification/scifact_pilot/run01_flash_direct/metrics.json) 均保留。

**网关标识限制：** 29 次响应的模型字段为 `deepseek-v4.1-flash`，1 次为
`deepseek-v4-flash-0731`（case `scifact-train-738-33912020`）。请求配置没有改变。
当前无法确定这是返回命名差异还是实际路由差异，不能将这轮称为已验证的单一底层模型实验。
后续受控比较需先确认这一点；本轮记录不删除、不重新挑结果。

只有该 1 次调用返回 token usage：输入 576、输出 342，共 918，其中报告 reasoning 283。
其余 29 次未知。918 不是整轮消耗，不据此估算总费用。

## 结果

| 项目 | 观测 |
|---|---|
| 有效结构与句子引用 | 30/30；0 执行错误、0 无效输出 |
| 与官方三分类标签一致 | 25/30，83.3% |
| Macro-F1 | 0.836 |
| 判为支持的标签精度 | 8/8；支持召回 8/10 |
| 非支持样本被判成支持 | 0/20 |
| 标签正确且依据句集合恰好匹配某组人工 rationale | 11/20 个有 rationale 的样本 |
| 已输出依据的程序定位重建 | 19/19；其余 11 条返回信息不足，无依据句 |
| 平均 / 中位 / 最大单条耗时 | 5.94 / 4.13 / 26.65 秒 |
| 整轮墙钟时间 | 101.55 秒 |

混淆矩阵：行是官方标签，列是预测标签。

| 官方标签 | 支持 | 反驳 | 信息不足 |
|---|---:|---:|---:|
| 支持 | 8 | 0 | 2 |
| 反驳 | 0 | 9 | 1 |
| 信息不足 | 0 | 2 | 8 |

这些数字描述这 30 条公开训练样本上的标签一致性。样本很小、类别经过平衡、领域偏基础生物医学，
并且可能进入模型预训练，不能据此声称临床可靠性、真实使用错误率或概率校准。
0/20 错误接受和 8/8 支持精度都不是“系统不会误判”的证据。

19/19 原文定位由程序保证；它不回答被定位的原文是否足以支持 claim。
另有 6 条关系标签正确但选取的句子集合不同：752、1333、1248、917、375、595。
它们均选择了某组参考依据及额外句子，不能因集合不完全相同就直接认定语义核查失败。
这里的数字是 SciFact claim ID，完整 case ID 可在清单中查到。

## 五条标签分歧：先记录，暂不重标

以下解释来自本次 AI 对原文与输出的审阅，属于诊断假设，不是新的专家金标签。
官方标签保持原样，分数仍按原标签计算。

| 完整 case ID | 官方 → 模型 | 原文中可观察到的问题与待核实项 |
|---|---|---|
| `scifact-train-1258-12040627` | 支持 → 信息不足 | claim 写 Kat8，摘要写 Mof；模型指出文本没有建立二者关系。需要定义、验证并单独测量实体别名知识的使用边界。 |
| `scifact-train-738-33912020` | 支持 → 信息不足 | claim 是 actin dynamics，摘要描述 CRMP2、氧化和 growth cone collapse。模型认为摘要没有明确建立 claim 所需关系；可能涉及任务允许的领域推理边界。该条同时有网关模型字段差异，不能将结果单独归因于某模型。 |
| `scifact-train-1309-18231807` | 信息不足 → 反驳 | 模型把 antigen-independent signaling 与 constitutive stimulation 联系后推得反驳；需要区分原文明示矛盾与加入领域解释后的矛盾。 |
| `scifact-train-1027-3113630` | 信息不足 → 反驳 | 模型从“磷酸化抑制活性”和“活性提高导致去磷酸化”作连锁推断；是否足以反驳目标干预陈述需有明确标注规范。 |
| `scifact-train-635-1686997` | 反驳 → 信息不足 | claim 与摘要使用不同酶名；模型先判断实体不一致，再拒绝迁移摘要中的结果。需先核实实体差异与原标注依据，不能自动当成模型过度保守。 |

复核发现，SciFact 的标签与我们“仅指定文本、限制外部知识”的严格任务并不处处等价。
这不证明 SciFact 不可靠，也不证明模型的分歧判断正确；它说明使用现成基准时仍需对齐任务。
不能靠允许任意外部知识把分数调高，也不能删除难题后宣称性能提高。

## 因此调整的下一步

1. **先写标注边界与基准适用性规则。** 区分原文明示、实体别名、领域桥接、推理链条和实体失配。
   本轮 30 条全部保留为已暴露的开发材料；任何更严格文本子集只能另列探索性分析，不能取代全量分数。
2. **建立可追溯的受控诊断对。** 从文本中明确的数字、方向、对象、单位等构造变体，加入等价改写与不充分情形。
   构造记录需要说明为什么标签成立；不确定的例子单列，不自动凑成黄金题。
3. **再比较核查设计。** 保持 claim、摘要、模型、预算不变，比较直接 Flash、结构化核查与专用核查器。
   在新增保留样本上测量；先确认网关返回模型标识的稳定性，保留缺失 usage，不假定费用相同。
4. **有了可解释的结果再接 UI。** 显示关系、原文和未解决问题，不显示未经校准的可信度百分比。
   后续补上 claim 提取遗漏、检索损失与答案修复的独立评估。

当前已具备可运行、可复查的独立核查研究起点。还没有足够证据给核查器贴上“可信”标签，
更没有证据证明 Agent 设计优于直接模型。后续实验允许得到“某个模块没有收益”的结论。

## 复现

见 [数据与命令说明](../../data/verification/scifact_pilot/README.md)。准备数据后，无需 API 即可
重算整轮分数并展开任何 claim 的原始句子、参考 rationale 和模型依据。

```sh
python scripts/verification/prepare_scifact.py
python scripts/verification/report_fixed_evidence.py --run data/verification/scifact_pilot/run01_flash_direct
python scripts/verification/inspect_case.py scifact-train-635-1686997 --run data/verification/scifact_pilot/run01_flash_direct
```

原文偏移使用规范化摘要的 Unicode code point。前端不能直接当作 JavaScript UTF-16 偏移使用。
试跑后新增的 `inspect_case.py` 是离线查看工具，不参与该轮推理；推理时使用的代码哈希见运行记录。
