# v0.8 里程碑：仓库审查与整理

日期：2026-09-27。起点：`e12c7d9` / 已发布的 `v0.8.0`。
本轮是该 tag 之后的维护，列在 [CHANGELOG / Unreleased](../CHANGELOG.md)；没有重打 tag。

## 判断

项目可以作为个人研究展示继续维护，**不需要推倒重写，但已经到了需要明确模块和文档边界的阶段**。
当前可维护的主线是 Ask → 保存答案版本 → 用户逐条审计 → 原文定位与导出。
研究已有可追溯输入、实际输出、对照和负结果；仍不能据此宣称医学审计可靠或 Agent 优越性。

审查时最集中的技术债务在 `agent/nodes.py` 的多职责和 `evidence.py` 的逐步增加的窄规则。
实验代码看起来重复，部分是冻结比较对象；真正该优先清理的是活跃启动入口、过时接口语义、
展示逻辑与页面状态混合，以及历史文档对当前版本的误导。随后按用户的清债要求完成了模块拆分
与文档收拢，见下方第二阶段记录。

## 覆盖范围

清点了全部已跟踪文件、代码体量/重复函数、文档入口/本地链接及数据目录；按入口追查 Ask 图、
上下文、会话持久化、审计/研究 API、MCP、检索/索引、旧 benchmark 与报告脚本。
研究核对包含原始记录可读性、代表性协议/标签边界、主要结果离线重算、历史快照与版本 tag。
未把未跟踪的用户前端目录/ZIP 纳入清理，未删除原始实验、失败或出版方文本。

这不是每个历史平台/模型均重新执行的声明。旧大语料抓取/建库、Docker、外部 MCP 客户端、
macOS/Linux 浏览器与付费推理没有在本轮重跑；医学来源及标签也未获得新的专家复核。

## 已修正的具体问题

| 发现 | 处理与影响 |
|---|---|
| MCP `ask_agent` 仍以公共 `thread_id`（默认同一个值）作为 checkpoint；空列表不能清除 additive 状态 | 改为每次独立 UUID，公共标签仅作 trace metadata；与 Web 共用初始状态。真实内存图的两次同标签调用证实旧 history/rewrite/repair 不再继承 |
| MCP 模块导入会自动加载本地模型；查询 PII 处理位置与文档相反，注释称满足合规；视觉占位的拒绝缺日志 | 改成模块按需加载、直接执行才预热；重写真实控制边界，拒绝也记录，保留 `stub` 标识；不再声称控制覆盖网页或构成合规证明 |
| 三个启动器复制端口、npm、子进程退出逻辑；独立 Audit 漏掉后端等待 | 集中到 `local_services.py`；等待 API、明确重置所有 Vite 演示标志，保留各自端口/索引 |
| 旧 `/api/history` 名称易让人误以为是当前网页聊天历史 | 标 deprecated 并更新 OpenAPI/前端类型；保留原 endpoint 兼容，明确 IndexedDB 才是网页持久化 |
| Audit 页面内混合状态与纯展示，CSS 多次追加相同 selector/移动端断点；窄屏答案工具栏挤出 Re-run | 拆出状态措辞、绑定展示与 Unicode 引句渲染；合并覆盖式样式，工具栏空间不足时换行 |
| 模型工厂开头仍把“think”解释为更强 Pro，并有未使用的 `_BACKEND` 缓存 | 注释改为当前 Flash 双角色与旧适配的区别；删未使用缓存，模型选择行为不变 |
| v0.8 报告信任保存的缓存 metrics，按记录行数判断完成 | 按冻结任务去重/核对输入与来源，从 audit 重算每项机械分数；重复不能填补缺失，分数不一致直接报错，原预测不改 |
| 演示打包遇到缺审计文件会静默跳过 | 按原协议推导每轮应有审计，全部读入/验证成功后才写导出；保留 partial/error 结果，不伪造成功 |
| 端口/MCP 旧说明、新旧设计和候选期状态混放 | 重写当前指南；增加代码/脚本/数据地图、研究总览和版本历史；旧报告只补历史标识，不洗掉原始失败与当时决定 |

## 数据与报告核对结果

- 本轮读入原有跟踪数据：282 个 JSON、88 个 JSONL 文件、7,260 条 JSONL 记录，无解析失败。
  这只说明结构可读，不证明标签或模型输出正确。
- v0.4 Flash 三个主要运行从保存原答和来源裁决重算：15/15 开发、10/10 重复、31/35 首次最终；
  与原 `flash_scored.json` 一致。这些裁决仍是开发 AI 复核，不是独立专家 gold。
- v0.6 固定目标最终结果重算仍为 Flash 291/339、MiniCheck 279/339；
  whole-answer、消融、预算和事后标签敏感性报告均可离线重算，派生数据无内容变化。
- v0.7 三臂最终仍为 35/40、35/40、31/40 正确接受，错误接受均 2/19，派生数据无内容变化。
- v0.8 的 development 144 / natural 36 / repeat 24 / final 144 共 348 次预定审计，从实际 judgment
  重算后，汇总 JSON 与研究报告文本均与发布版本一致。11 个冻结推理/计分文件均未改变。
- 三份会话重新打包并通过导入合同，导出内容未变。原始 XML、失败运行、旧源码和标签未改。
- 早期 `report_release.py --check` 通过；它只核对该历史报告，不能替代以上各代不同研究合同。

结果不需要为了里程碑重写成正向故事：Direct/Flash 仍默认，Atomic 的机械收益和额外待审负担
同时存在；规定工具流程尚未胜过简单对照；R3 因新公开标签不足而暂缓。
统一解释见 [研究总览](research-overview.md)，追溯路径见 [数据目录](../data/README.md)。

## 功能确认

首阶段离线套件加针对缺陷的回归：276 项 Python、7 项前端通过，前端生产构建通过。
主要新增反例是 MCP 状态继承、被拒绝的占位调用日志、研究重复记录和篡改缓存分数。
有一条上游 Starlette/AnyIO deprecated 警告，不影响这些结果。

无 ML 的轻量环境实际启动回放 API，读取三组会话；浏览器实际打开 GRADE 会话、Direct/Atomic v2
切换、限定语定位与返回原答，桌面/390px 窄屏均查看，无 console error。没有新模型调用，
因此不把这次维护描述成新增 Agent 效果评测。

## 第二阶段：实际拆分与文档收拢

原 nodes 1,355 行改为 `nodes/`，按计划、检索、提纲、生成、检查、历史划分，最大实现文件
224 行；原 evidence 519 行改为 models / binding / scope / restoration，最大 237 行。
46 个保留函数/类逐个比对执行 AST，逻辑未变，仅修正旧角色说明；三个无生产调用的 planner helper 移除，
其中“用邻近数字句替换请求项”的旧逻辑不再留作容易误用的后门。五个仅覆盖该废弃 helper
的用例一并移除，现有用户行为回归保留。测试 mock 指向实际实现模块。

AnswerPanel 从 535 行降到 186 行，纯展示分到 `components/answer/`；AuditPage 负责执行和
页面状态，claim 详情、来源定位分别进入 ClaimList / SourceList。公共 Python 导入保持兼容，
未来 benchmark 收集全部新包源码，历史源码快照不修改。

文档顶层从清理前 81 份收拢到 19 份。60 份文档归类迁移，其中当前架构替代旧架构；
11 个旧路径通过删除/合并/替换退出维护。配置集中到 configuration；报告和逐题答案进入
reports；日志和日期方案进入 archive。重要协议、版本记录、失败案例、原始数据继续保留，
删除的早期大说明有固定 tag 链接。生成脚本和当前文档同步新路径，不保留大批重复跳转页。

拆分后 271 项 Python、7 项前端用例及生产构建通过；少的五项来自已移除的死代码测试，
不是跳过失败行为。报告生成入口已实际重算；v0.6/v0.7 报告只变链接，v0.8 汇总数据相同。
11 个冻结推理/计分文件仍保持原哈希，跟踪数据的变化只有 README 链接。
拆分后再次打开真实 GRADE 会话，切换 Direct / Atomic v2、定位来源与限定语、返回原答，
并查看 390px 页面；浏览器无 console error。本地 Markdown 743 个路径引用均可解析。

下一阶段的 [v0.9 计划](plans/v0.9-question-coverage.md)聚焦请求覆盖，明确新参照可行性、
直接/结构化/同调用次数对照、错误放行和正确接受指标。当前只完成设计，没有新的付费研究运行。

## 继续保留的边界

1. **旧入口兼容成本：** MiMo、旧 conda/Docker/编号脚本、图内 summarize 节点仍在。
   有历史调用者/实验意义，不能仅因主展示不用就删掉；不再把它们当新用户默认路径。
2. **本地产品边界：** 单标签页编辑、浏览器存储容量、停止后已发出的同步模型调用可能继续；
   目前没有服务端账户同步、通用迁移或公共部署能力。本轮不引入相应企业化设施。
3. **核心研究缺口：** 自然医学整段语义标签、窄规则可靠性、歧义追问/子问题遗漏，以及审计指导修复的独立收益。
   先研究这些具体失败，再决定是否增加复杂模块；不以更多文档或检查替代效果证据。
