# 技术路线：先测量审计，再让审计参与研究

更新：2026-09-27。[v0.7.1](releases/v0.7.1.md) 修正产品入口；
v0.6 → v0.7 研究保留在 [v0.7.0](releases/v0.7.0.md)。[v0.8 详细计划](plans/v0.8-conversation-and-audit.md) 已制定，尚未实施。
Flash / Direct 继续作为默认。新方法的存在、更多结构化字段或一次演示成功，不构成可靠性结论。

## 最终形态

一个可以逐条审阅答案的医学文献工作台：claim 对应原回答和来源原句，来源身份、支持关系、
未解决项与执行过程都能查看、导出。同时有独立于系统核查器的测量，说明哪些判断可靠、哪些容易失败。
在能力范围得到证据支持后，才让审计参与补检索、回答修复和研究问题综合。

产品主线始终是 Ask → 回答 → 答案内审计 → 继续提问。Audit lab 与 Research 是辅助工作台，
不能因为研究需要独立评测而取代对话入口。见 [产品方向纠正](decisions/2026-09-27-conversation-first-product.md)。

用户无法提供新的专家团队。优先复用公开人工标注，制作变换与来源明确的构造诊断，
把 AI 开发复核与独立标签分开。模型投票、自报置信度和多次一致不能充当 gold。
临床证据分级、因果适用范围、跨文献可比性另设任务，不与原文定位捆绑验收。

## 已实现的三条路径

| 路径 | 做什么 | 如何解释 |
|---|---|---|
| 完整 Ask（产品主流程） | BGE/Qdrant 检索、重排、LangGraph 回答；当前回答内展开 Audit | v0.4 结果是其历史 AI 来源审阅，不是新审计器的可靠率 |
| 独立文本审计 | 固定 claim/摘要核查，以及整段 Direct、Split、Context、quote-v2、Atomic 审计 | 判断给定文本支持什么；精确位置不是语义正确性 |
| v0.7 受限研究工作流 | 同一 Flash、固定候选库与工具下，一次读取、自主工具、规定流程三臂比较 | 指定论文事实查询；没有宣称评估历史完整 Ask 或开放医学研究 |

原子审计保留原句、多片段、规范化解释、限定词与未检查项。MiniCheck 是可选的独立模型对照，
轻量回放不依赖它的权重。产品上的核查器分歧不等于文献间冲突，也不自动合成置信度。

原文位置按 Unicode code point 计数；前端用 `Array.from` 对应。重复/缺失引文不猜位置。
原句绑定可以成功而规范化事实仍丢限定词，必须分别报告。

## 三类证据

| 证据 | 本轮用途 | 不能据此声称 |
|---|---|---|
| SciFact 公开标签 | 固定 claim 对照、分数拟合、独立阈值选择、工作流关系评价 | 无训练污染、临床事实真伪、整段解释全部正确 |
| 来源明确的医学构造 | 改写、组别/数值、人群/时间、证据移除与拆分诊断 | 专家 gold 或自然错误发生率 |
| RAGTruth 与真实 Ask 输出 | 自然回答定位、重复变化、真实医学交互演示 | 字符重叠就是抓到具体错误；无标错警报全是假阳性 |

按全部关联文献连通组隔离，同一来源及变体不能跨区。开发、校准和最终评估分开；
失败、需复核、未提取均留在原分母。最终输出曝光后只作回归，不反复调参当新测试。

MiniCheck 的 raw score 只是文本支持分类分数。阈值需在独立区选择，再在冻结最终区评估；
没有达到预定风险与样本量要求，就报告无可用规则。界面不使用未经验证的可信度百分比。

## 版本路径与范围调整

本轮已测得边界：固定 339 对中 Flash / MiniCheck 的二分类正确为 291 / 279；独立阈值
选择没有可用 MiniCheck 接受规则。自然回答中 Atomic 全检查完成 11/36，Direct 为 34/36。
40 题工作流的正确接受为直接阅读 35、自主工具 35、规定流程 31，错误接受同为 2/19。
因此不升级默认，不自动用核查器改写答案，也不发布无依据的可信度百分比。

| 阶段 | 交付 / 目标 |
|---|---|
| [v0.5 已发布](releases/v0.5.0.md) | 文本核查、自然回答诊断、原文联动、真实医学 Ask → Audit 回放 |
| [v0.6 研究](plans/v0.6-audit-reliability.md) | 原子与限定词诊断、Flash/MiniCheck、分区/校准、消融与重复；随 v0.7.0 合并交付 |
| [v0.7 本轮](plans/v0.7-agent-comparison.md) | 指定论文任务的同工具比较、真实 trace 与分母/成本公开、三类医学演示 |
| [v0.7.1 产品修正](releases/v0.7.1.md) | Ask 恢复主入口，答案内展开审计；不等于完整历史与多轮上下文已完成 |
| [v0.8 已制定](plans/v0.8-conversation-and-audit.md) | 多轮记录与追问、逐轮审计持久化、父句定位和限定语保真；交付有限研究及真实对话回放 |
| v0.9 后续候选 | 在核查能力有据可查后，建立不指定目标论文的补检索任务与受约束修复比较 |
| v1.0 愿景 | 可审阅的完整文献研究流程、多研究综合、独立可靠性测量与可导出审计记录 |

早期设想 v0.7 直接让审计驱动开放检索和自动修复。本轮作了明确范围调整：核查仍会误判和
丢限定词，现有公开标签也不能独立评分开放问题的完整答案。因此先交付可独立评分的受限工具比较，
保留原答和分歧，完整 Ask 对照与自动修复后移。[决定依据](decisions/2026-09-26-v07-research-scope.md)。

下一阶段的改进要分别回答：提取是否保留全部限定；补检索是否找到原先缺少的证据；
修复是否消除已有错误又保留正确内容、是否产生新错误。简单方案必须留作对照，模型与工具权限、
实际计算量分别记录。核查器不能同时生成修复结果并给自己的修复充当最终裁判。

v0.8 先解决已经暴露的产品缺口：当前后端每问独立初始化，thread ID 不能当成真实对话记忆。
因此先交付显式历史、上下文追问与每轮审计保存，再推进定位/保真研究；新增开放补检索和自动修复
后移至后续候选版本，不再为了增加研究模块而牺牲 Ask 主流程。

优先做三个窄改进：在已唯一定位的父句内绑定短片段，避免全答案中的重复词造成无谓失败；
保留每个限定语及其原文对应，显式暴露拆分丢失；区分真正关系冲突与正确支持被误拦。
本轮已曝光样本用于回归，新方法的效果结论仍需要另留来源，不能在这些最终题上调到满意为止。

60 个 RAGTruth test 来源继续保留；未经充分验证的整段语义评分不应为了发布版本而提前使用它们。
证据分级与跨研究冲突裁决需要独立任务定义和方法学依据，前端出现字段不代表该能力已经实现。
