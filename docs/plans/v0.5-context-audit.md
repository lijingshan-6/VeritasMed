# v0.5：语境保留、元文本分流与 Ask → Audit

2026-09-24，调用模型前登记。本轮是开发实验，仍使用 Flash，最多 3 个同时请求，无 Pro 回退。

## 要解决的问题与交付

上一轮的 24 份 RAGTruth 回答中，出现归因/时态丢失、字数说明被当作文献事实核查、原标注与报错范围粒度不同等问题。先生成逐条差异台账，保留原标注、原始输出和判断理由；台账是开发诊断，不是新的专家标签。

原 `answer_audit.py`、`ragtruth.py` 和 `ragtruth_v1/run01` 保持不变。新增单次调用的实验策略：

1. **Context only**：提供按换行分段的完整回答语境，claim 精确绑定所属段落；核查时保留归因、条件、否定、预测/计划及时间，禁止将被报道的指控当成作者断言。语境绑定是位置约束，不能保证模型语义判断正确。
2. **Meta only**：将当前回答自身的引导语、格式/字数说明单列，不要求外部来源证明；不得将来源中的数值、研究事实或不确定的事实当作元文本排除。
3. **Context + meta**：两项同时启用。元文本保留原文位置、分类理由，不计入来源支持判断。字数仅报告明示规则的计数，不猜测作者的字数口径。

Direct 仍是对照和产品默认。所有策略使用相同来源、模型和调用上限；改进是否成立由数据决定。

产品接通 Ask → Audit：原回答、全部实际检索片段、来源编号和会话出处原样传递；不自动发送模型、不静默截断、不自动改写答案。超过输入上限时明确说明。引导演示与实际 Ask 必须区分。

## 固定数据和调用数

- 回归：原 24 份开发回答，新增三种策略，共 72 次调用；Direct 使用已保存的原始结果，注明跨批次比较的限制。
- 新开发批次：从同一固定版本的 RAGTruth 官方 train / good / Summary 中按固定哈希顺序选 24 个新来源，12 份有错误标注、12 份无错误标注；排除上一轮所有来源和所有官方 test 来源。Direct 与 Context + meta 各 24 次，共 48 次，同批次交错执行。
- 稳定性：在新批次中按固定哈希抽取 3+3 份，再独立执行 Context + meta，共 6 次。
- 合计 126 次逻辑调用；SDK 网络重试另按已有配置。先冻结输入哈希、代码、提示词、顺序与配置，再执行。失败记录保留，不选择性重跑。
- 原先预留的 60 个官方 test 来源本轮不执行。公开训练数据不能作为最终独立临床评估。

## 评分与决策

复用原 scorer：全部官方错误范围始终在分母中，报告任意交集/至少一半范围召回、字符 precision/recall/F1、无错误标注回答的警报比例、失败、token 与耗时。元文本若覆盖官方错误，必须单列数量，不从分母删除。回答级“有警报”与确实定位到人工错误分开。

消融在原 24 份上观察两项改动的边际影响；新批次作主要迁移观察。稳定性报告警报字符集合重叠、回答级警报一致性及指标波动，不包装成置信度校准。

只有当新批次半范围召回不低于 Direct，且无错误标注回答警报数量减少、字符 F1 提高，才讨论升级默认；24 份数据即使满足条件，也只支持开发选择，不证明临床可靠。未满足则保留 Direct，发布失败分析和可选实验模式。
