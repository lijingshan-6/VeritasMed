# VeritasMed 技术路线：先测量文本审计，再研究审计驱动的问答

决定日期：2026-09-24。状态：v0.5 开发中；已发布版本仍为 v0.4.0。

## 最终形态与本阶段边界

最终产品是一个逐条 claim 的审计工作台：答案陈述与原文句子双向定位，展示来源、
支持关系、未解决问题和审计过程。每项可靠性声明必须对应实际测量。
在核查器有明确的适用范围后，再让它指导补充检索、答案修复和研究问题综合。

用户无法提供独立医学专家标注。本路线不以新增专家团队为启动条件：优先复用已有人工
标注、建设标签构造依据明确的诊断集，并把专业方法学判断从首期验收中分离。
多个模型同意、模型自报置信度以及我对新案例的审阅，都不能自动变成独立人工黄金标签。

v0.5 只回答：**指定文献的文本是否支持这条陈述，依据在哪里？**

| 内容 | 当前处理 |
|---|---|
| 来源、引文、句子位置和上下文 | 程序核对文献版本与精确位置 |
| 单文献的支持、反驳、信息不足 | 主要测量对象；判断仅限提供的文本 |
| 原文明示的数字、单位、人群、时间和比较对象 | 诊断重点；后续规则只标记明确失配 |
| 回答完整性 | 单独任务，不能用 claim 支持率代替 |
| 因果解释、证据分级、临床适用性 | 本阶段不输出经过验证的自动结论 |
| 跨文献可比性与冲突裁决 | 后续专项；首期仅允许带来源并列展示差异 |

文献说了某句话不证明其医学结论真实。未在提供文本中找到支持，也不证明全球文献无证据。
“尚未核查”“执行失败”与“信息不足”必须区分，不能将接口故障算作合理保留判断。

## 技术结构

独立模块 `src/medrag/verification/` 不依赖问答 graph、Qdrant 或 GPU。
先接收给定的 claim 和完整摘要，随后才引入自动 claim 提取和检索。

1. 输入包含 claim、文献 ID、原始句子序列；提示词不包含标签、正确依据或数据划分。
2. 模型返回支持关系、依据句 ID 与简短解释，不让模型重新编造引文。
3. 程序从冻结文本解析句 ID，生成原文、字符范围和文献内容 SHA-256。
4. 句 ID 越界、结构无效或请求失败单独保存，不修补为正确结果。
5. 分数只在独立评分程序中计算，核查器不读取参考标签。
6. 保存初始输出、设置和代码哈希；将来再记录修复前后结果，禁止仅保存成功重试。

字符范围以 `"\n".join(sentences)` 的 Unicode code point 计数。前端接入时必须显式
转换为 JavaScript UTF-16 范围或按句 ID 渲染，不能直接混用偏移单位。

当前标注规则见 [文本核查边界 v1](verification-label-policy.md)。[第二轮诊断](verification-v0.5-diagnostics.md)
已完成直接 Flash 与结构化方案的比较：三组同为 48/48，未发现字段提示或聚合的准确率收益。
继续保留 direct 主基线；结构化模式作研究选项。后续增加自然回答与复合 claim，再决定模块取舍。

## 三类证据，三套报告

**公开人工标注。** 首先接入 SciFact 的 claim/文献对和依据句。只使用官方引用文献与
标注证据文献的并集；引用文献未被标为支持/反驳时，标签仅表示该摘要信息不足。
不把任意未标注检索结果一律判成负例。原始标签不因模型输出而改写。
官方 train/dev 标签可用，test 标签不公开；本地结果不称为官方 test 成绩。
公开数据可能出现在基础模型或专用核查模型训练中，必须披露，不能当作全新泛化证据。

首轮试跑发现别名知识、隐含领域推理与严格文本任务之间有分歧，见
[试跑报告](verification-v0.5-pilot.md)。使用人工标注不能省略任务对齐；官方标签保留，
不根据模型输出重标。后续按预先定义的知识依赖类型分析，另列探索子集，不替换全量结果。

**受控诊断集。** 从明确可定位的事实构造正确/错误配对，记录唯一变更、正确槽位和
排除规则。区分错引用、数值失配、语义矛盾和信息不足；改过的句子不自动判错。
四舍五入、单位等价、其他队列或上下文支持不清楚的构造不能进入确定标签集。
同一论文、原句和所有变体保持同组；正负样本的格式与词汇线索平衡。

**应用观察。** v0.4 的 50 题及新 Agent 输出用于回归与失败分析。未经独立确认的新
判断标注为 AI 来源审阅，不混入人工标注基准的可靠率，不以多模型投票代替正确标签。

## 比较与消融

先在相同 claim 和相同完整摘要上比较直接 Flash、现有检查思路的独立适配器、专用
事实核查模型及结构化核查方案。保留官方句子顺序，不只提供正确 rationale，避免泄漏。
Flash 是默认研究模型；没有 Pro 自动回退。GPU 模型作为后续独立对照，本阶段不要求 GPU。

然后分离加入 claim 提取、检索和修复，测各阶段损失。完整系统阶段才比较模型自主工具
调用与规定流程：固定语料、工具和模型，比较不同调用预算下的效果及耗时。
外部更强模型的结果单列，不把模型变化归因于 Agent 设计。

记录网关实际返回的模型字段和缺失用量。首轮曾出现返回标识不一致，原因尚未确认；
在解释受控比较前需确认是否存在命名或路由差异，不能仅凭请求参数断言底层模型完全一致。

消融按机制做：无原子拆分、无数字/范围检查、无补充证据搜索、无保留判断、无针对性修复。
没有增益的模块可移除。最终裁判始终不能是正在比较的核查器本身。

## 测量与产品表达

- 关系分类混淆矩阵、逐类 precision/recall/F1、支持标签精度与错误接受率。
- 依据句与人工 rationale 的对应情况；允许多组合法 rationale，保留替代依据争议。
- 精确引文定位完整性独立报告，不能充当语义支持准确率。
- 执行/结构错误、判断覆盖率、延迟、调用数和已报告用量；缺失用量保持 unavailable。
- 未来 claim 提取测遗漏，回答修复测新错误和内容损失，避免少说或拒答换取高支持率。

正式比较按文献/相关 claim 分组，校准与最终测试分离；先注册指标及阈值再运行保留集。
试验轮数、排除项与失败完整保留。小型试跑只证明链路可运行并暴露问题，不宣称可靠率。
概率校准完成前，界面不显示“94%可信”。显示关系、原文与未解决问题；跨文献差异不自动
升级为冲突，来源数量不代表独立研究数量或证据等级。

## 版本顺序与完成形态

| 阶段 | 交付 |
|---|---|
| v0.5 | 文本审计契约、公开数据适配、受控诊断、固定证据对照、真实记录面板 |
| v0.6 | 更完整核查实验、独立校准与适用范围、可单独审计任意答案 |
| v0.7 | 审计驱动的检索与修复、强模型自主工具调用对照 |
| v1.0 | 文献研究流程、引用联动、多研究综合与可导出审计记录 |

v0.5 的交付是一个能测、能查原文、能说明不足的文本审计系统。证据分级与跨文献
可比性需另设任务、标签来源和外部依据；不会因为前端已有占位字段就宣称已实现。
